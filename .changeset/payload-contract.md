What a droplet sends the browser now keeps its types: a `Date`, `Map`, `Set`, `URL` or `BigInt` in the server load's data or in an action's result, nested anywhere, reaches the browser's `load`, `form`, `onResult` and `updateForm` as the same type. On the wire each one travels in its JSON form, and the envelope (the fragment's data payload, `_data`, an action's JSON answer) lists where they are under a new `"transported"` key, absent when there is nothing to list, so a plain payload is unchanged. Only the browser turns them back; the server never reads anything a request carries that way. See "What data can be" in Writing droplets and "Transported values" in the HTTP contract.

Breaking: the server load's data is now checked on every render, as an action's result already was. A value that cannot travel (a function, a symbol, a promise, an instance of any other class or a subclass of a built-in, a cycle, `undefined` or a hole in an array, `NaN`, `Infinity`, an invalid `Date`, an object with its own `toJSON`, nesting deeper than 64) fails the render with the new error `payload-not-serializable`, which names the path and the reason: the droplet renders its `+error` page, and `_data` answers `500`. Before, `JSON.stringify` turned such a value into something else without a word (a `Date` into a string, a `Map` into `{}`, `NaN` into `null`, a function into nothing); data that relied on that now needs to be turned into plain values in the load. An action's result follows the same contract: the error `action-data-not-json` is retired, a `Date`, `Map`, `Set`, `URL` or `BigInt` in a result is now accepted, and anything else answers `500` with `payload-not-serializable`. A shared reference is copied, not refused.

A result that goes back to the server stays plain JSON: the signed result in the page's URL after a post without JavaScript, and the `form` a droplet that does not hydrate sends with its fragment request. A result holding a `Date`, `Map`, `Set`, `URL` or `BigInt` goes without its data there, with a `form-result-not-plain` warning under `vite dev`. A payload the browser cannot decode logs the new error `payload-undecodable`; for the inline payload the element then asks `_data`. The element has a new `decodePayload(envelope)` method, which `enhanceDropletForm` calls on an action's answer; the `droplets:action` event's `data` stays the answer's JSON as it came.

`rendererConformance()` now requires the transported built-ins in `hello`: its `+droplet.server.ts` returns a `Date`, a `Map`, a `Set`, a `URL` and a `BigInt`, its `+droplet.ts` reads them into `kinds`, and the component renders `kinds` in `[data-testid="kinds"]`; a renderer's own suite fails until its fixture adds it (the layout is in `conformance.ts`).
