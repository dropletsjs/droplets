How a plain PHP site embeds droplets: the page fetches its fragments with
curl and prints them into the template.

## The pattern in PHP

```php
// app/shop.php (trimmed)
function shop_fragments(array $wanted): array
{
    $headers = ['accept' => 'text/html', 'x-host' => shop_origin(), 'referer' => shop_origin() . shop_raw_target()];
    $cookie = shop_request_header('cookie');
    if ($cookie !== null) {
        $headers['cookie'] = $cookie;
    }
    $requests = [];
    foreach ($wanted as $key => [$id, $pairs]) {
        $requests[$key] = ['url' => shop_internal_url() . '/droplets/' . rawurlencode($id) . '?' . shop_build_query($pairs), 'headers' => $headers];
    }
    $responses = http_all($requests); // app/http.php: curl_multi, CURLOPT_FOLLOWLOCATION => false

    $results = [];
    foreach ($wanted as $key => [$id]) {
        $response = $responses[$key];
        $status = $response['status'] ?: 502;
        $result = ['html' => '', 'status' => $status, 'location' => null, 'cookies' => $response['headers']['set-cookie'] ?? [], 'link' => http_header($response, 'link')];
        $is_html = str_starts_with((string) http_header($response, 'content-type'), 'text/html');
        if ($status >= 300 && $status < 400) {
            $result['location'] = http_header($response, 'location');
        } elseif ((($status >= 200 && $status < 300) || $status === 500) && $is_html) {
            $result['html'] = $response['body'];
            $results[$key] = $result;
            continue;
        }
        // … anything else: $result['html'] becomes a "droplet is unavailable" note
        $results[$key] = $result;
    }
    return $results;
}
```

```php
<!-- app/views/shop/layout.php, in <head>: once per page -->
<script type="module" src="/index.js"></script>
<!-- app/views/shop/gallery.php: the fragment's HTML, as it came -->
<aside><?= $fragments[0] ?></aside>
```

- `shop_fragments()` sends `GET /droplets/<id>?<params>` for every fragment
  at once to `SHOP_INTERNAL_URL`, with `accept: text/html`, `x-host` set to
  this host's public origin (`shop_origin()`, from `SHOP_PUBLIC_URL`), the
  browser's `Cookie` as it came, and the page's path and query as `referer`
  (`shop_raw_target()` is `$_SERVER['REQUEST_URI']`).
- curl never follows a redirect, so a droplet's 3xx is kept: `shop_render()`
  answers it with a `Location` header, and sends the fragments'
  `Set-Cookie` with the page.
- Only a `text/html` answer (a 2xx, or a 500 carrying the droplet's error
  page) is pasted; `<?= ?>` prints it unescaped.
- `app/views/shop/layout.php` loads `/index.js` once. `shop_is_proxied()`
  sends `/index.js`, `/droplets/*`, `/assets/*` and `/api/*` to
  `shop_proxy()`, which passes them on to the shop.

## The shop demo, recorded

has the diagram.

No framework and no Composer: PHP files on the official `php:8.3-apache`
image, and curl, which the image already has. Apache sends every path that
is not a file in `public/` to `public/index.php`; the shop's pages and its
proxy are `examples/hosts/php/app/shop.php`, the curl helper `app/http.php`,
the templates `app/views/shop/`.

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8009, public (Apache on 80 inside) | PHP: the shop's pages, the proxy, and the basic page at `/` |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, public | the Svelte example's droplets server, for `/` only |

| On `web` | Value | Used for |
| --- | --- | --- |
| `SHOP_INTERNAL_URL` | `http://shop:8300` | internal: fragment fetches and the proxy |
| `SHOP_PUBLIC_URL` | `http://localhost:8009` | public: this host's own origin, sent as `x-host` |
| `DROPLETS_INTERNAL_URL`, `DROPLETS_PUBLIC_URL` | `http://droplets:8000`, `http://localhost:8000` | the same pair, for the basic page |

The official image passes the container's environment to PHP, so
`getenv()` reads them. Behind php-fpm, set them with `env[…]` in the pool
or `SetEnv` in Apache.

### How a page gets a droplet

Each page's fragments, the toasts and the header's cart badge included, go
out at once with `curl_multi`. The fetch is `shop_fragments()` and the view
is `app/views/shop/gallery.php`, both shown in the pattern above; the
fragments' `Link` preloads go into `<head>`. The `/gallery` route asks for
its two:

```php
shop_render('gallery', 'Gallery', '/gallery', [['product-filter', $query], ['product-library', $query]]);
```

`referer` is the page's path and query as the browser sent it
(`REQUEST_URI`): the droplet's
[`host`](/integrate/http-contract/#host-where-the-droplet-renders).
`app/views/shop/layout.php` loads `<script type="module" src="/index.js">`
once, through the proxy, and each droplet hydrates itself. The `toast-center`
fragment comes first in its body; `/index.js` installs
`window.shopMessageQueue` before any droplet starts (the shop's
`src/hooks.client.ts`):

```php
<body class="shop">
<?= $toasts ?>
<header class="shop-header">…<div class="shop-cart"><?= $cart ?></div>…</header>
```

The pages are `/gallery`, `/product/<slug>` (with `v` passed on when the
link has it), `/cart` (the cart as `variant=inline`), `/login` and `/admin`.

### What it proxies

`shop_is_proxied()` matches `/index.js`, `/droplets/*` (fragments, `_data`,
form actions), `/assets/*` and `/api/*`, for every method, before any page
route. `shop_proxy()` passes the request on with an allowlist of the
browser's headers and `x-host` written out, and the body from
`php://input` as it came. The answer comes back with its status, every
`Set-Cookie` and any redirect untouched, and without the per-hop headers
(`Connection` and what it names, `Keep-Alive`, `Transfer-Encoding`,
`Upgrade` and the rest), nor `Content-Length` and `Content-Encoding`, which
no longer hold once curl has decoded the body. The shop's cookies are
first-party, and nothing is cross-origin; the shop sets them only from form
actions and `/api`, which come through here.

### The shop's environment

- `DROPLETS_TRUSTED_ORIGINS: http://localhost:8009`: the only origin whose
  [`x-host`](/integrate/http-contract/#x-host-the-public-location) and
  [form posts](/integrate/http-contract/#form-posts-the-origin-check) the shop accepts.
- `DROPLETS_SECRET`: signs a form's result on the redirect back to the page
  when JavaScript is off ([Post/Redirect/Get](/integrate/http-contract/#postredirectget)).
- `ADMIN_USER`, `ADMIN_PASSWORD`, `SHOP_SECRET`: the demo login
  (admin / droplets) and the key its cookie is signed with. Demo values only.

### Gotchas

- **PHP parses multipart posts into `$_POST` and `$_FILES`** and leaves
  `php://input` empty, which would lose the admin's image upload on its way
  through the proxy. `php.ini` turns `enable_post_data_reading` off: the
  host never reads a form itself, and every body stays in `php://input`.
- **No cookie jar.** No curl handle has `CURLOPT_COOKIEFILE`,
  `CURLOPT_COOKIEJAR` or a share handle, and each lives for one request:
  a `Set-Cookie` from one visitor's answer is never sent with another's.
  The browser's own `Cookie` header is what goes out. (A long-running PHP
  server that reuses handles across requests must keep it that way.)
- **`$_GET` merges repeated keys and renames `a.b` to `a_b`.** The shop's
  pages read `QUERY_STRING` themselves (`shop_query()`) and pass the pairs
  on as they came.
- **`<?= ?>` does not escape.** That is how the fragments are pasted; the
  templates escape everything else with `h()`. See [For hosts](/guides/security/#for-hosts).
- **`public/` is the document root**, so `app/` is never served, and
  `FallbackResource` routes any method to `index.php` with `REQUEST_URI`
  as the browser sent it.

### Run it

```bash
cd examples/hosts/php
docker compose up --build
open http://localhost:8009/gallery   # log in as admin / droplets
```

## The Svelte example

The same app serves the Svelte example at `/`: its three droplets, one per mode, from `examples/frameworks/svelte` (the `droplets` service), all three fetched at once.

```php
// public/index.php
$droplets_internal = rtrim(getenv('DROPLETS_INTERNAL_URL') ?: 'http://localhost:8000', '/');
$droplets_public = rtrim(getenv('DROPLETS_PUBLIC_URL') ?: 'http://localhost:8000', '/');

$ids = array_map(fn($framework) => "{$framework}-ssr-hydrate", ['svelte', 'vue', 'react', 'solid', 'handlebars']);
$responses = http_all(array_map(fn($id) => [
    'url' => $droplets_internal . '/droplets/' . rawurlencode($id) . '?' . http_build_query(['who' => $who]),
    'headers' => ['x-host' => $droplets_public],
], $ids), 5);
```

```php
<script type="module" src="<?= h($droplets_public) ?>/index.js"></script>
...
<?php foreach ($fragments as $fragment): ?>
    <?= $fragment ?>
<?php endforeach; ?>
```

Laravel, Symfony or any other PHP framework works the same way: fetch in
the controller (Guzzle's `Pool` or Symfony's HttpClient run several at
once), print the body unescaped (`{!! $fragment !!}` in Blade, `|raw` in
Twig).

The example lives in `examples/hosts/php`. The page and the droplets server are
different origins, so the droplets server runs with `cors: true`.
