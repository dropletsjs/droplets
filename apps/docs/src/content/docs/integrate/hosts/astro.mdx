## How this host is set up

The code is in `examples/hosts/astro/src`: the pages, `lib/shop-page.ts` (the
Astro side) and `lib/shop.ts` (the framework-free fetches and proxy).

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8005, public | Astro with the Node adapter (`output: "server"`): the shop's pages, the proxy, and the basic page at `/` |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, public | the Svelte example's droplets server, for `/` only |

| On `web` | Value | Used for |
| --- | --- | --- |
| `SHOP_INTERNAL_URL` | `http://shop:8300` | internal: fragment fetches and the proxy |
| `SHOP_PUBLIC_URL` | `http://localhost:8005` | public: this host's own origin, sent as `x-host` |
| `DROPLETS_INTERNAL_URL`, `DROPLETS_PUBLIC_URL` | `http://droplets:8000`, `http://localhost:8000` | the same pair, for the basic page |

### How a page gets a droplet

A server fetch in the page's frontmatter, rendered with `set:html`:

```astro
---
// src/pages/gallery.astro
const query = new URLSearchParams(Astro.url.search);
const page = await shopPage(Astro.request, [
  ["product-filter", query],
  ["product-library", query],
]);
const answered = finish(Astro, page); // Set-Cookie onto Astro.response, or the droplet's redirect
if (answered) return answered;
const [filter, library] = page.fragments;
---
<aside><Fragment set:html={filter} /></aside>
<div><Fragment set:html={library} /></div>
```

`shopPage` fetches each fragment (and the toasts and the header's cart badge) in parallel
from `SHOP_INTERNAL_URL` with `x-host`, the browser's `Cookie`, the page's
URL as `Referer` (the droplet's
[`host`](/integrate/http-contract/#host-where-the-droplet-renders), query
included) and `redirect: "manual"`, and pastes only `text/html` answers.
`src/layouts/Shop.astro` writes the fragments' `Link` preloads into the head
and loads `<script type="module" src="/index.js">` once, through the proxy.
The `toast-center` fragment comes first in its body; `/index.js` installs
`window.shopMessageQueue` before any droplet starts (the shop's
`src/hooks.client.ts`):

```astro
<body class="shop">
  <Fragment set:html={toasts} />
  <header class="shop-header">…<div class="shop-cart"><Fragment set:html={cart} /></div>…</header>
```

### What it proxies

Endpoints that export `ALL` forward `/index.js` (`src/pages/index.js.ts`),
`/droplets/*` (fragments, `_data`, form actions), `/assets/*` and `/api/*`
(`src/pages/{droplets,assets,api}/[...path].ts`) to `shop.proxy(request)`:
bodies streamed, `x-host` written out, `Set-Cookie` and redirects passed back
untouched. The shop's cookies are first-party, and nothing is cross-origin;
the shop sets them only from form actions and `/api`, which come through here.

### The shop's environment

- `DROPLETS_TRUSTED_ORIGINS: http://localhost:8005`: the only origin whose
  [`x-host`](/integrate/http-contract/#x-host-the-public-location) and
  [form posts](/integrate/http-contract/#form-posts-the-origin-check) the shop accepts.
- `DROPLETS_SECRET`: signs a form's result on the redirect back to the page
  when JavaScript is off ([Post/Redirect/Get](/integrate/http-contract/#postredirectget)).
- `ADMIN_USER`, `ADMIN_PASSWORD`, `SHOP_SECRET`: the demo login
  (admin / droplets) and the key its cookie is signed with. Demo values only.

### Gotchas

- **The public origin is read at runtime.** Astro's own form check
  (`security.checkOrigin`) trusts the request's host only when
  `security.allowedDomains` lists it, and that list is compiled in at build.
  So `astro.config.mjs` turns it off and `src/middleware.ts` runs the same
  check against `SHOP_PUBLIC_URL` from the environment: one image runs under
  any origin. The shop checks `Origin` again on its side.
- **Cookies go through `Astro.response.headers`**, appended as the shop sent
  them; a droplet's redirect is returned as a `Response` with its own status.

### Run it

```bash
cd examples/hosts/astro
docker compose up --build
open http://localhost:8005/gallery   # log in as admin / droplets
```

## The Svelte example

The same app serves the Svelte example at `/`: its three droplets, one per mode, from `examples/frameworks/svelte` (the `droplets` service), fetched in the page's frontmatter.

With `output: "server"` and the Node adapter, an Astro page runs per request
and can fetch fresh fragments in its frontmatter.

```astro
---
import { DROPLETS_PUBLIC_URL, fragment } from "../lib/droplets.ts";

const who = Astro.url.searchParams.get("who") ?? "Astro";
const ids = ["client", "ssr-hydrate", "ssr-nohydrate"];
const fragments = await Promise.all(ids.map((id) => fragment(id, { who })));
---

<html lang="en">
  <head>
    <script type="module" src={`${DROPLETS_PUBLIC_URL}/index.js`} is:inline></script>
  </head>
  <body>
    {fragments.map((html) => <Fragment set:html={html} />)}
  </body>
</html>
```

`is:inline` tells Astro to leave the external module script alone instead of
bundling it. `fragment()` is the usual helper: `GET /droplets/<id>` on the
internal address with `x-host` set to the public one.

```ts
export async function fragment(droplet: string, props: Record<string, string> = {}) {
  const url = new URL(`/droplets/${encodeURIComponent(droplet)}`, DROPLETS_INTERNAL_URL);
  for (const [key, value] of Object.entries(props)) url.searchParams.set(key, value);
  const response = await fetch(url, { headers: { "x-host": DROPLETS_PUBLIC_URL } });
  return response.ok ? response.text() : `<p class="error">droplet "${droplet}" unavailable</p>`;
}
```

The example lives in `examples/hosts/astro`. The page and the droplets server are
different origins, so the droplets server runs with `cors: true`.
