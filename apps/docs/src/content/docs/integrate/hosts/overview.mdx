Eleven host examples; nine run the shop demo; WordPress and htmx have flows
of their own. Each is a folder in `examples/hosts/` with a
`docker-compose.yml` and an end-to-end test, and each page in this section
starts with the pattern in that stack: the fetch, the paste and the script
tag, taken from the example's code. [Any other stack](/integrate/any-stack/)

## Three variations

**Server include.** The host's server fetches the fragment and renders it into
its template. Express, Astro, SvelteKit, Next.js, FastAPI, Sinatra, plain
PHP and the WordPress plugin all do this. It is the default choice: the page
arrives rendered, and droplets that never hydrate, and forms through
[Post/Redirect/Get](/guides/actions/#without-javascript-postredirectget),
work without JavaScript.

**Reverse proxy.** The host proxies the droplets routes under its own origin
and, if it can, includes fragments itself. nginx does both with Server Side
Includes and `proxy_pass`, with zero application code. No CORS is involved
because the browser only ever talks to one origin.

**Client-only.** A single-page app has no server to paste fragments into. It
writes the droplet element (`<djs-droplet>` by default, named per server by
`element`) with `data-droplet` and `data-droplet-props` directly, or fetches the
fragment from the browser, and lets the element do the rest. The React
example shows both. [htmx](/integrate/hosts/htmx/) does the second with no code
at all: `hx-get` asks for the fragment and swaps it into a static page.

## Passing content in

A host can put its own content inside a droplet, other droplets included, in
one `<div data-droplet-slot>` before the element's closing tag. The component
decides where it shows. See [Host children](/guides/in-the-browser/#host-children).

## Choosing when it hydrates

`data-droplet-hydrate="visible"` or `"interactive"` on the element defers a droplet's
JavaScript until it scrolls into view or someone interacts with it, whatever
the component declares. See [Lazy hydration](/guides/in-the-browser/#lazy-hydration).

## While developing

Point the host at `vite dev` instead of a build
(`http://localhost:5173/index.js`, fragments from `localhost:5173`) and the
droplets update in place while you edit them. `index.js?injectTool=true` adds
the dev tool to the host page. See [Development](/guides/development/#hot-updates).

## Two origins

Inside Docker, the host reaches the droplets server at `http://shop:8300`
while browsers reach it through the host's own origin. Each example's
compose file sets the pair for the host and `DROPLETS_TRUSTED_ORIGINS` for
the droplets server; [the environment](/integrate/any-stack/#the-environment)
says what each one does.

[Security model](/guides/security/) says what crosses between the host and
the droplets server: cookies, caching, CORS and who sees what.

and `pnpm test:hosts <id>`.

## Running the examples

Each example folder in the repository is standalone, with its own dependencies
and a `docker-compose.yml` that starts it next to a droplets server built from
the Svelte example, `examples/frameworks/svelte`, and the shop:

```bash
cd examples/hosts/<id>
docker compose up --build
```

Set `SHOP_SECRET` and `DROPLETS_SECRET` first (32 or more random characters
each, `openssl rand -hex 32`; WordPress takes `WP_SHOP_HOST_SECRET` and
`WP_SHOP_SERVICE_SECRET` instead of the first), in the environment or a `.env`
file beside `docker-compose.yml`: compose refuses to start without them.
`pnpm test:hosts` generates its own for a run.

All of them render the same three droplets on `/`, one per mode: `client`
(rendered in the browser), `ssr-hydrate` (server-rendered, then hydrated) and
`ssr-nohydrate` (server-rendered, no JavaScript). The interactive ones call the droplets server's `/api` endpoints
through [`$droplets/drop`](/reference/api/#dropletsdrop), on the origin the
page loaded `/index.js` from, so a host that proxies the droplets server
under its own origin proxies `/api/*` too.

`pnpm test:hosts` runs the nine shop flows one after the other;
`pnpm test:hosts wordpress` and `pnpm test:hosts htmx` run the other two
([tests/hosts](/integrate/hosts/shop-demo/#each-host-recorded)).
