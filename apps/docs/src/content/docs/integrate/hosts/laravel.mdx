How a Laravel app embeds droplets: a controller fetches its fragments with
Laravel's HTTP client, all at once, and a Blade view prints them into the
page.

## The pattern in Laravel

```php
// app/Shop.php (trimmed)
public function fragments(Request $request, array $wanted): array
{
    $headers = ['accept' => 'text/html', 'x-droplet-location' => $this->origin, 'referer' => $this->origin.$request->getRequestUri()];
    $cookie = $this->cookieHeader($request);
    if ($cookie !== null) {
        $headers['cookie'] = $cookie;
    }
    $answers = Http::pool(fn (Pool $pool) => array_map(function (int $key) use ($pool, $headers, $wanted) {
        [$id, $pairs] = $wanted[$key];
        $query = $pairs === [] ? '' : '?'.self::buildQuery($pairs);

        return $this->client($pool->as("f$key")->withHeaders($headers), 10)->get($this->internalUrl.'/droplets/'.rawurlencode($id).$query);
    }, array_keys($wanted)));

    $results = [];
    foreach ($wanted as $key => [$id]) {
        $answer = $answers["f$key"] ?? null; // a Response, or the ConnectionException of a failed one
        $status = $answer instanceof ShopResponse ? $answer->status() : 502;
        // … $result: html, status, location, cookies (every Set-Cookie), link
        if ($status >= 300 && $status < 400) {
            $result['location'] = $received['location'][0] ?? null;
        } elseif ((($status >= 200 && $status < 300) || in_array($status, [500, 504], true)) && $isHtml) {
            $result['html'] = $answer->body();
            $results[$key] = $result;
            continue;
        }
        // … anything else: $result['html'] becomes a "droplet is unavailable" note
        $results[$key] = $result;
    }
    return $results;
}

// No redirect followed, no cookie kept.
private function client(PendingRequest $request, int $timeout): PendingRequest
{
    return $request->withoutRedirecting()->connectTimeout(5)->timeout($timeout)
        ->withOptions(['cookies' => false, 'expect' => false]);
}
```

```blade
{{-- resources/views/shop/layout.blade.php, in <head>: once per page --}}
<script type="module" src="/index.js"></script>
{{-- resources/views/shop/gallery.blade.php: the fragment's HTML, as it came --}}
<aside>{!! $fragments[0] !!}</aside>
```

- `fragments()` sends `GET /droplets/<id>?<params>` for every fragment at
  once (`Http::pool`) to `services.shop.internal_url`, with
  `accept: text/html` and `x-droplet-location` set to `$this->origin`, the
  origin of `services.shop.public_url` (`SHOP_PUBLIC_URL`). It passes on the
  browser's `Cookie` cut down to the shop's own `cart_id` and `shop_admin`,
  and the page's URL as `referer`: that origin plus `getRequestUri()`, the
  path and query as the browser sent them.
- `withoutRedirecting()` keeps a droplet's 3xx: `ShopController::render()`
  answers it with its `Location`, and sends the fragments' `Set-Cookie` with
  the page.
- Only a `text/html` answer (a 2xx, or a 500 or 504 carrying the droplet's error
  page) is pasted; `{!! !!}` prints it unescaped.
- `resources/views/shop/layout.blade.php` loads `/index.js` once.
  `routes/web.php` sends `/index.js`, `/env.js`, `/index.css`,
  `/droplets/*`, `/assets/*` and `/api/*` to `ShopProxyController`, which
  passes them on to the shop.

## The shop demo, recorded

The [shop demo](/integrate/hosts/shop-demo/) on Laravel 13, recorded by the
end-to-end test. [How the pieces fit](/integrate/hosts/shop-demo/#how-it-fits-together)
has the diagram.

<HostDemo id="laravel" stack="Laravel 13" />

A Laravel 13 app on PHP 8.5 and Apache (`php:8.5-apache`, mod_php), with
the framework alone (`laravel/framework`, no starter kit) and its HTTP
client, which is Guzzle. Apache sends every path that is not a file in
`public/` to Laravel's `public/index.php`. The routes are
`examples/hosts/laravel/routes/web.php`, the pages
`app/Http/Controllers/ShopController.php`, the fragments and the proxy
`app/Shop.php`, the views `resources/views/shop/`.

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8013, public (Apache on 80 inside) | Laravel: the shop's pages, the proxy, and the basic page at `/` |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, public | the Svelte example's droplets server, for `/` only |

| On `web` | Value | Used for |
| --- | --- | --- |
| `SHOP_INTERNAL_URL` | `http://shop:8300` | internal: fragment fetches and the proxy |
| `SHOP_PUBLIC_URL` | `http://localhost:8013` | public: this host's own origin, sent as `x-droplet-location` |
| `DROPLETS_INTERNAL_URL`, `DROPLETS_PUBLIC_URL` | `http://droplets:8000`, `http://localhost:8000` | the same pair, for the basic page |

`config/services.php` reads them with `env()`, and the code reads the
config (`config('services.shop.public_url')`), as Laravel has it.

### How a page gets a droplet

Each page's fragments, the toasts and the header's cart badge included, go
out at once in one `Http::pool`. The fetch is `Shop::fragments()` and the
view is `resources/views/shop/gallery.blade.php`, both shown in the pattern
above; the fragments' `Link` preloads go into `<head>`. The gallery asks for
its two:

```php
// app/Http/Controllers/ShopController.php
public function gallery(Request $request): Response
{
    // The whole query to both: the shop drops what a droplet does not take.
    $query = $this->shop->query($request);

    return $this->render($request, 'gallery', 'Gallery', '/gallery', [['product-filter', $query], ['product-library', $query]]);
}
```

`referer` is the page's URL, query included. The shop's `handle` reads it
with `hostFrom`, so it is the droplet's
[`host`](/integrate/http-contract/#host-where-the-droplet-renders), and after
a form posted without JavaScript its query carries the form's result. The
layout loads `<script type="module" src="/index.js">` once, through the
proxy, and each droplet hydrates itself. The `toast-center` fragment comes
first in its body; `/index.js` installs `window.shopMessageQueue` before any
droplet starts (the shop's `src/hooks.client.ts`):

```blade
{{-- resources/views/shop/layout.blade.php --}}
<body class="shop">
{!! $toasts !!}
<header class="shop-header">…<div class="shop-cart">{!! $cart !!}</div>…</header>
<main class="shop-main shop-wrap">
@yield('content')
</main>
```

The pages, `GET` and `HEAD` only (`Route::get`), are `/gallery` (the whole
query to `product-filter` and `product-library`), `/product/{slug}` (`slug`
and `v` to `product-page`; `order`, `page`, `showing` and `productId` to
`product-comments`), `/cart` (the cart as `variant=inline`), `/login`
(`next`) and `/admin` (`view` and `id`). The product page first reads the
product from the shop's public `GET /droplets/product-page/_data?slug=<slug>`;
an unknown slug renders `not-found` with `404`. Every page and redirect is
sent `Cache-Control: private, no-store`: its fragments were rendered with
the visitor's cookies.

### What it proxies

```php
// routes/web.php
foreach (['/index.js', '/env.js', '/index.css'] as $file) {
    Route::any($file, ShopProxyController::class);
}
foreach (['droplets', 'assets', 'api'] as $prefix) {
    Route::any("/$prefix/{rest}", ShopProxyController::class)->where('rest', '.*');
}
```

`Route::any` takes every method, and these routes come before the pages:
`/index.js`, `/env.js`, `/index.css`, `/droplets/*` (fragments, `_data`,
form actions), `/assets/*` and `/api/*` go to `Shop::proxy()`. It passes
the request on with `x-droplet-location` written out and only these of the
browser's headers: `accept`, `accept-language`, `content-type`,
`if-none-match`, `origin`, `referer`, `user-agent`, `x-droplet-props` and
`x-droplets-build`, plus `cookie` cut down to the shop's own `cart_id` and
`shop_admin`, so another app's cookie on this origin stays here. The
method is `getRealMethod()`, the one on the wire, the body
`getContent()` as it came, and the target `getRequestUri()` concatenated
onto the shop's internal URL, never resolved, so `//elsewhere` stays a path
on the shop; a path with a `.` or `..` segment, once decoded, is refused
with `400`. A shop that does not answer within 15 seconds is `502`
`The shop is unreachable.` The answer comes back with its status, every
`Set-Cookie` and any redirect, and without the per-hop headers
(`Connection` and what it names, `Keep-Alive`, `Transfer-Encoding`,
`Upgrade` and the rest), nor `Content-Length` and `Content-Encoding`, which
no longer hold once the client has decoded the body. The shop's cookies are
first-party, and nothing is cross-origin; the shop sets them only from form
actions and `/api`, which come through here.

### Gotchas

- **The `web` middleware group is not for these routes.** Its
  `EncryptCookies` would encrypt the shop's `Set-Cookie` on the way out and
  drop its cookies on the way in, and `ValidateCsrfToken` would refuse every
  form post the shop's droplets send through the proxy (`419`). The routes
  load in `bootstrap/app.php` with `withRouting(using: …)` and no group:
  no session, no CSRF token, no cookie of Laravel's own. The shop checks
  its form posts against `Origin` itself.
- **The global middleware is cut down** to `ValidatePathEncoding` and
  `ValidatePostSize` (`$middleware->use([…])`): `TrimStrings` and
  `ConvertEmptyStringsToNull` parse a JSON body before any route is chosen,
  and `HandleCors` would answer `/api/*` with CORS headers of Laravel's own
  (its default `config/cors.php` covers `api/*`) instead of the shop's.
- **No cookie jar.** Laravel builds a Guzzle client for each request with
  `'cookies' => true`, a jar of its own; `withOptions(['cookies' => false])`
  turns it off, so what goes out is the browser's own `Cookie`, cut down to
  `cart_id` and `shop_admin`, and a `Set-Cookie` from one visitor's answer
  is never sent with another's.
- **A Laravel response has no raw `Set-Cookie`.** Symfony keeps cookies as
  objects and writes them out itself, so `Shop::passCookies()` parses each
  of the shop's (`Cookie::fromString`): name, value as it came, Path,
  Domain, Expires and Max-Age, Secure, HttpOnly, SameSite and Partitioned
  survive; Symfony writes the attribute names in lower case and a cleared
  cookie as `deleted` with `Max-Age=0`. Symfony also adds `private` to a
  `Cache-Control` that names neither `public` nor `private`, and
  `no-cache, private` where there is none.
- **PHP parses multipart posts into `$_POST` and `$_FILES`** and leaves
  `php://input` empty, which would lose the admin's image upload on its way
  through the proxy. `php.ini` turns `enable_post_data_reading` off: the
  host never reads a form itself, and `getContent()` holds every body.
- **`$request->query()` is PHP's `$_GET`**, which merges repeated keys and
  renames `a.b` to `a_b`. `Shop::query()` reads `QUERY_STRING` itself and
  passes the pairs on as they came.
- **`getMethod()` follows `X-HTTP-Method-Override` and `_method`** on a
  `POST` (Laravel turns the `_method` parameter on, for HTML forms); the
  proxy sends `getRealMethod()`, the one on the wire.
- **`{!! !!}` does not escape.** That is how the fragments are pasted;
  everything else goes through `{{ }}`. See [For hosts](/guides/security/#for-hosts).
- **The config is not cached** (`php artisan config:cache` would freeze the
  build's environment); the Dockerfile caches the routes and the views only.

### Run it

```bash
cd examples/hosts/laravel
docker compose up --build
open http://localhost:8013/gallery   # log in as admin / droplets
```

Set `SHOP_SECRET` and `DROPLETS_SECRET` first; compose refuses to start
without them. The shop trusts one origin besides its own,
`DROPLETS_TRUSTED_ORIGINS: http://localhost:8013`, this host's; the rest of
its environment is the same on every host: see
[Running a host](/integrate/hosts/shop-demo/#running-a-host).

The app's own feature tests (`tests/Feature/`, with `Http::fake()`: the
headers and cookies that go out, the per-hop headers that do not come back,
the dot segments refused, a non-HTML answer never pasted) run in the
image's `test` stage:

```bash
docker build --target test .
```

## The Svelte example

The same app serves the Svelte example at `/` (`GET` and `HEAD`): its three
droplets, one per mode, from `examples/frameworks/svelte` (the `droplets`
service), all three fetched at once.

```php
// app/Http/Controllers/HomeController.php
$internalUrl = rtrim((string) config('services.droplets.internal_url'), '/');
$publicUrl = rtrim((string) config('services.droplets.public_url'), '/');
$who = $request->query('who');
$who = is_string($who) ? $who : 'Laravel';

$answers = Http::pool(fn (Pool $pool) => array_map(
    fn (string $id) => $pool->as($id)
        ->withHeaders(['accept' => 'text/html', 'x-droplet-location' => $publicUrl])
        ->withoutRedirecting()
        ->timeout(10)
        ->get($internalUrl.'/droplets/'.rawurlencode($id).'?'.http_build_query(['who' => $who])),
    self::IDS,
));
// … only a 2xx, 500 or 504 text/html answer becomes a fragment; anything else a <p class="error">
```

```blade
{{-- resources/views/index.blade.php --}}
<script type="module" src="{{ $dropletsPublic }}/index.js"></script>
…
@foreach ($fragments as $fragment)
    {!! $fragment !!}
@endforeach
```

Here the page loads `/index.js` from the droplets server's public URL,
another origin than the page, so the Svelte example runs with `cors: true`
and `DROPLETS_TRUSTED_ORIGINS` lists both `DROPLETS_URL` and this host's
`WEB_URL`.

Plain PHP without a framework is the [PHP](/integrate/hosts/php/) host:
the same shop with `curl_multi`.
