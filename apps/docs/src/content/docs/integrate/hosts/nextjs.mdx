How a Next.js App Router app embeds droplets: a server component fetches
each fragment and emits it as HTML.

## The pattern in Next.js

```ts
// lib/shop.ts, fragment() (trimmed)
async function fragment(page: PageRequest, id: string, params = new URLSearchParams()): Promise<Fragment> {
  const url = `${internal}/droplets/${encodeURIComponent(id)}?${params}`;
  const headers: Record<string, string> = { accept: "text/html", "x-droplet-location": origin, referer: origin + page.path };
  if (page.cookie) headers["cookie"] = page.cookie;
  const result: Fragment = { html: "", status: 502, location: null, cookies: [], link: null };
  const response = await fetch(url, { headers, redirect: "manual", cache: "no-store" });
  result.status = response.status;
  result.cookies = response.headers.getSetCookie();
  result.link = response.headers.get("link");
  if (response.status >= 300 && response.status < 400) {
    result.location = response.headers.get("location");
  } else if (
    (response.ok || response.status === 500) &&
    (response.headers.get("content-type") ?? "").startsWith("text/html")
  ) {
    result.html = await response.text();
    return result;
  }
  // … anything else: result.html becomes a "droplet is unavailable" note
  return result;
}
```

```tsx
// app/(shop)/layout.tsx, in <head>: once per page
<script type="module" src="/index.js" />
// app/(shop)/gallery/page.tsx: the fragment's HTML, as it came
<aside>
  <Fragment html={fragments[0]!} />
</aside>
```

- `shopPage()` in `lib/shop-page.tsx` takes `page` from the page's own path
  and query and the browser's `Cookie` (from `headers()`). `fragment()` sends
  `GET /droplets/<id>?<params>` to `SHOP_INTERNAL_URL` with
  `accept: text/html`, `x-droplet-location` set to this host's public origin
  (`SHOP_PUBLIC_URL`), that `Cookie`, and the page's URL as `referer`.
  `cache: "no-store"` keeps Next from caching it.
- `redirect: "manual"` keeps a droplet's 3xx, which `shopPage()` answers with
  Next's `redirect(location, RedirectType.replace)`.
- Only a `text/html` answer (a 2xx, or a 500 carrying the droplet's error
  page) is pasted; `Fragment` writes it with `dangerouslySetInnerHTML`.
- Route handlers (`app/index.js/route.ts`, `app/env.js/route.ts`,
  `app/index.css/route.ts`, `app/droplets/[[...path]]`, `app/assets/[...path]`,
  `app/api/[...path]`) pass `/index.js`, `/env.js`, `/index.css`,
  `/droplets/*`, `/assets/*` and `/api/*` on to the shop.

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8007, public | Next.js (App Router): the shop's pages, the proxy, and the basic page at `/` |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, public | the Svelte example's droplets server, for `/` only |

| On `web` | Value | Used for |
| --- | --- | --- |
| `SHOP_INTERNAL_URL` | `http://shop:8300` | internal: fragment fetches and the proxy |
| `SHOP_PUBLIC_URL` | `http://localhost:8007` | public: this host's own origin, sent as `x-droplet-location` |
| `DROPLETS_INTERNAL_URL`, `DROPLETS_PUBLIC_URL` | `http://droplets:8000`, `http://localhost:8000` | the same pair, for the basic page |

### How a page gets a droplet

A server fetch in a server component, emitted with `dangerouslySetInnerHTML`:

```tsx
// app/(shop)/gallery/page.tsx
const query = queryOf(await searchParams);
const { toasts, cart, fragments, preloads } = await shopPage(`/gallery${query.size ? `?${query}` : ""}`, [
  ["product-filter", query],
  ["product-library", query],
]);

// lib/shop-page.tsx
export function Fragment({ html }: { html: string }) {
  return <div style={{ display: "contents" }} suppressHydrationWarning dangerouslySetInnerHTML={{ __html: html }} />;
}
```

`shopPage` fetches the page's fragments, plus `toast-center` and
`shopping-cart` with `variant=badge` for the header, in parallel
(`Promise.all`) with `x-droplet-location`, the browser's `Cookie` (from
`headers()`) and the page's path and query as `Referer`: the droplet's
[`host`](/integrate/http-contract/#host-where-the-droplet-renders). It never
follows redirects and pastes only `text/html` answers; anything else becomes
a "droplet is unavailable" note. The product page first reads
`GET /droplets/product-page/_data?slug=…` through `findProduct`, wrapped in
React's `cache()` so the page and its `generateMetadata` share one lookup,
and calls `notFound()` when there is none. The `Link` preloads (only
`preload` and `modulepreload`, only on this host's origin) render as
`<link>` elements, which React hoists into the head, and the
`(shop)` root layout loads `<script type="module" src="/index.js">` once,
through the proxy. `ShopShell` puts the `toast-center` fragment first in the
body; `/index.js` installs `window.shopMessageQueue` before any droplet starts
(the shop's `src/hooks.client.ts`):

```tsx
// lib/shop-page.tsx, ShopShell
<Fragment html={toasts} />
<header className="shop-header">…<Fragment html={cart} />…</header>
```

### What it proxies

Route handlers (`app/index.js/route.ts`, `app/env.js/route.ts`,
`app/index.css/route.ts`, `app/droplets/[[...path]]`, `app/assets/[...path]`,
`app/api/[...path]`, all `force-dynamic`) pass
`/index.js`, `/env.js`, `/index.css`, `/droplets/*` (fragments, `_data`, form actions), `/assets/*`
and `/api/*` to the shop. Each is the same file:

```ts
// app/droplets/[[...path]]/route.ts
export const dynamic = "force-dynamic";

const proxy = (request: Request) => shop.proxy(request);

export { proxy as GET, proxy as HEAD, proxy as POST, proxy as PUT, proxy as PATCH, proxy as DELETE, proxy as OPTIONS };
```

`shop.proxy` in `lib/shop.ts` sends `x-droplet-location` (the origin of
`SHOP_PUBLIC_URL`) and passes on only `accept`, `accept-language`,
`content-type`, `if-none-match`, `origin`, `referer`, `user-agent`,
`x-droplet-props` and `x-droplets-build`, plus `cookie` cut down to the
shop's own `cart_id` and `shop_admin`: nothing that names a host, and no
other app's cookie on this origin. The body streams through
(`duplex: "half"`), redirects are not followed, each request times out (15
seconds; fragments 10, the product lookup 5), and the answer comes back
with its `Set-Cookie` untouched, minus
`content-encoding`, `content-length` and the hop-by-hop headers. When the
shop is down it answers `502`. The shop's cookies are first-party, and
nothing is cross-origin.

### The shop's environment

- `DROPLETS_TRUSTED_ORIGINS: http://localhost:8007`: the only origin whose
  [`x-droplet-location`](/integrate/http-contract/#x-droplet-location-the-public-location) and
  [form posts](/integrate/http-contract/#form-posts-the-origin-check) the shop accepts.
- `DROPLETS_SECRET`: signs a form's result on the redirect back to the page
  when JavaScript is off ([Post/Redirect/Get](/integrate/http-contract/#postredirectget)).
- `ADMIN_USER`, `ADMIN_PASSWORD`, `SHOP_SECRET`: the demo login
  (admin / droplets) and the key its cookie is signed with. Demo values only.

### Gotchas

- **A server component cannot set cookies.** Only Server Actions, Route
  Handlers and middleware may; the page streams, so its headers may be gone.
  A fragment's `Set-Cookie` on a page render is dropped (`shopPage` logs a
  warning). The shop sets cookies only from form actions and `/api`, which go
  through the route handlers, so its cart and login work. A droplet that sets
  a cookie on a plain `GET` would need its page served from a Route Handler
  instead, giving up React for that page.
- **A server component cannot set `Cache-Control` either.** The shop pages
  carry a visitor's cart and session, so `next.config.ts` gives `/gallery`,
  `/product/:slug`, `/admin` and `/login` `private, no-store` through
  `headers()`, as every other host sets it on its shop pages.
- **A droplet's redirect goes out as Next's 307**: `redirect()` takes no status.
- `suppressHydrationWarning` on the wrapper: the droplets hydrate themselves
  and may change their markup before React compares it.
- **A fragment that is not pasted is read, not cancelled.** Next's `fetch`
  hands back a tee of the body, and cancelling one branch waits for the
  other forever, so `fragment()` reads the small body with
  `response.arrayBuffer()` instead.
- `lib/droplets.ts`, `lib/shop.ts` and `lib/shop-page.tsx` import
  `server-only`, so none of them can end up in a client component.

## The Svelte example

The same app serves the Svelte example at `/` (the `(basic)` route group): its three droplets, one per mode, from `examples/frameworks/svelte` (the `droplets` service).

A server component runs on the Next server, fetches the fragments and emits
them with `dangerouslySetInnerHTML`. The droplets hydrate on their own in the
browser.

```tsx
// lib/droplets.ts
import "server-only";
…
export async function fragment(
  droplet: string,
  props: Record<string, string> = {},
): Promise<string> {
  const url = new URL(`/droplets/${encodeURIComponent(droplet)}`, DROPLETS_INTERNAL_URL);
  for (const [key, value] of Object.entries(props)) url.searchParams.set(key, value);
  try {
    // Fragments are per-request content; never let Next cache them.
    const response = await fetch(url, {
      headers: { accept: "text/html", "x-droplet-location": DROPLETS_PUBLIC_URL },
      cache: "no-store",
      redirect: "manual",
      signal: AbortSignal.timeout(5000),
    });
    // Only an HTML answer is a fragment (a 500 carries the droplet's error
    // page); anything else may echo the props, so it is never pasted.
    const isFragment =
      (response.ok || response.status === 500) && (response.headers.get("content-type") ?? "").startsWith("text/html");
    if (isFragment) return await response.text();
    // Read, not cancelled: Next's fetch hands back a tee of the body, and
    // cancelling one branch waits for the other, forever. It is small.
    await response.arrayBuffer();
    return `<p class="error">droplet "${escapeHtml(droplet)}" unavailable: HTTP ${response.status}</p>`;
  } catch (error) {
    return `<p class="error">droplet "${escapeHtml(droplet)}" unavailable: ${escapeHtml(String(error))}</p>`;
  }
}
```

```tsx
// app/(basic)/page.tsx
// The Svelte example's droplets (examples/frameworks/svelte), one per mode.
const IDS = ["client", "ssr-hydrate", "ssr-nohydrate"];

export default async function Page({ searchParams }: { searchParams: SearchParams }) {
  const params = await searchParams;
  const who = typeof params.who === "string" ? params.who : "Next.js";

  const fragments = await Promise.all(
    IDS.map((id) => fragment(id, { who })),
  );

  return (
    <main style={{ maxWidth: "48rem", margin: "0 auto" }}>
      …
      <div suppressHydrationWarning dangerouslySetInnerHTML={{ __html: fragments.join("") }} />
    </main>
  );
}
```

```tsx
// app/(basic)/layout.tsx
<head>
  <script type="module" src={`${DROPLETS_PUBLIC_URL}/index.js`} />
</head>
```

`cache: "no-store"` keeps the fragment out of Next's data cache: a cached
fragment would show stale data and a stale build hash.

The example lives in `examples/hosts/nextjs`, with `output: "standalone"`
(and `outputFileTracingRoot` set to the folder) for the Docker image, which
runs `node server.js`. Here the page loads `/index.js` from the droplets
server's own origin (`http://localhost:8000`), so the browser fetches
bundles and data across origins: the Svelte example runs with `cors: true`,
and the `droplets` service lists both `DROPLETS_URL` and `WEB_URL` in
`DROPLETS_TRUSTED_ORIGINS`.
