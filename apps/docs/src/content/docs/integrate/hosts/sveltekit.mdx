## How this host is set up

The code is in `examples/hosts/sveltekit/src`: `hooks.server.ts`, the `(shop)`
route group, `lib/shop-page.server.ts` (the SvelteKit side) and
`lib/shop.server.ts` (the framework-free fetches and proxy).

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8006, public | SvelteKit with adapter-node: the shop's pages, the proxy, and the basic page at `/` |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, public | the Svelte example's droplets server, for `/` only |

| On `web` | Value | Used for |
| --- | --- | --- |
| `SHOP_INTERNAL_URL` | `http://shop:8300` | internal: fragment fetches and the proxy |
| `SHOP_PUBLIC_URL` | `http://localhost:8006` | public: this host's own origin, sent as `x-host` |
| `ORIGIN` | `http://localhost:8006` | adapter-node's origin, which SvelteKit checks form posts against |
| `BODY_SIZE_LIMIT` | `4M` | above the 512 KB default, for the admin's image uploads |
| `DROPLETS_INTERNAL_URL`, `DROPLETS_PUBLIC_URL` | `http://droplets:8000`, `http://localhost:8000` | the same pair, for the basic page |

### How a page gets a droplet

A server fetch in `+page.server.ts`, rendered with `{@html}`:

```ts
// src/lib/shop-page.server.ts, called from each (shop) +page.server.ts load
export async function shopFragments(event: RequestEvent, wanted: [id: string, params: URLSearchParams][]) {
  const page = { path: event.url.pathname + event.url.search, cookie: event.request.headers.get("cookie") };
  const results = await Promise.all(wanted.map(([id, params]) => shop.fragment(page, id, params)));
  (event.locals.shopCookies ??= []).push(...results.flatMap((result) => result.cookies));
  const moved = results.find((result) => result.location);
  if (moved) redirect(moved.status as Redirect, moved.location!);
  return { fragments: results.map((result) => result.html), head: shop.linkTags(results) };
}
```

```svelte
<!-- src/routes/(shop)/gallery/+page.svelte -->
<aside>{@html data.filter}</aside>
```

`shop.fragment` sends `x-host`, the browser's `Cookie` and the page's URL
as `Referer` (the droplet's
[`host`](/integrate/http-contract/#host-where-the-droplet-renders), query
included), never follows redirects, and returns only `text/html` answers.
The `(shop)` layout puts the `Link` preloads in `<svelte:head>` and loads
`<script type="module" src="/index.js">` once, through the proxy. Its
`+layout.server.ts` fetches the toasts and the header's cart badge, and the
`toast-center` fragment comes first in the layout, and `/index.js` installs
`window.shopMessageQueue` before any droplet starts (the shop's
`src/hooks.client.ts`):

```svelte
<!-- src/routes/(shop)/+layout.svelte -->
{@html data.toasts}
<header class="shop-header">…<div class="shop-cart">{@html data.cart}</div>…</header>
```

### What it proxies

`handle` in `src/hooks.server.ts` sends `/index.js`, `/droplets/*`
(fragments, `_data`, form actions), `/assets/*` and `/api/*` to
`shop.proxy` before any routing: bodies streamed, `x-host` written out,
`Set-Cookie` and redirects passed back untouched. The shop's cookies are
first-party, and nothing is cross-origin; the shop sets them only from form
actions and `/api`, which come through here.

### The shop's environment

- `DROPLETS_TRUSTED_ORIGINS: http://localhost:8006`: the only origin whose
  [`x-host`](/integrate/http-contract/#x-host-the-public-location) and
  [form posts](/integrate/http-contract/#form-posts-the-origin-check) the shop accepts.
- `DROPLETS_SECRET`: signs a form's result on the redirect back to the page
  when JavaScript is off ([Post/Redirect/Get](/integrate/http-contract/#postredirectget)).
- `ADMIN_USER`, `ADMIN_PASSWORD`, `SHOP_SECRET`: the demo login
  (admin / droplets) and the key its cookie is signed with. Demo values only.

### Gotchas

- **`ORIGIN` and `BODY_SIZE_LIMIT`.** Without `ORIGIN`, SvelteKit rejects the
  shop's form posts as cross-site; without a higher `BODY_SIZE_LIMIT`,
  adapter-node cuts the admin's uploads off at 512 KB.
- **Fragment cookies go out from `handle`**, appended as they came, never
  through `cookies.set`, which would re-encode them.
- **Shop links reload the page** (`data-sveltekit-reload` in the layout), so
  each page is fetched with its fragments, as on every other host.

### Run it

```bash
cd examples/hosts/sveltekit
docker compose up --build
open http://localhost:8006/gallery   # log in as admin / droplets
```

## The Svelte example

The same app serves the Svelte example at `/`: its three droplets, one per mode, from `examples/frameworks/svelte` (the `droplets` service).

Droplets are Svelte components too, but from the outside a droplets server is
a remote service like any other. SvelteKit treats it as one.

```ts
// src/routes/+page.server.ts
import { DROPLETS_PUBLIC_URL, fragment } from "$lib/droplets.server.ts";
import type { PageServerLoad } from "./$types";

export const load: PageServerLoad = async ({ fetch, url }) => {
  const who = url.searchParams.get("who") ?? "SvelteKit";
  const fragments = await Promise.all(
    ["svelte", "vue", "react", "solid", "handlebars"].map((framework) =>
      fragment(fetch, `${framework}-ssr-hydrate`, { who }),
    ),
  );
  return { dropletsUrl: DROPLETS_PUBLIC_URL, fragments };
};
```

```svelte
<!-- src/routes/+page.svelte -->
<script lang="ts">
  let { data } = $props();
</script>

<svelte:head>
  <script type="module" src="{data.dropletsUrl}/index.js"></script>
</svelte:head>

{#each data.fragments as fragment}
  {@html fragment}
{/each}
```

The helper reads both addresses from `$env/dynamic/private` and uses the
`fetch` SvelteKit hands to `load`, so the fragments are fetched during server
rendering and never again on the client.

The example lives in `examples/hosts/sveltekit`. The page and the droplets server
are different origins, so the droplets server runs with `cors: true`.
