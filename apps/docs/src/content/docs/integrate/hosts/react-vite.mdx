How a React single-page app embeds droplets: a component fetches each
fragment from the browser, through a same-origin proxy, and inserts it.

## The pattern in React + Vite

```tsx
// src/shop/ShopDroplet.tsx (trimmed)
export function ensureShopClient(): void {
  if (document.querySelector('script[src="/index.js"]')) return;
  const script = document.createElement("script");
  script.type = "module";
  script.src = "/index.js";
  document.head.appendChild(script);
}

// ShopFragment: GET /droplets/<id>?<query>, inserted as it came.
useEffect(() => {
  ensureShopClient();
  const target = host.current;
  if (!target) return;
  fetch(`/droplets/${encodeURIComponent(id)}?${search}`, { redirect: "manual", headers: { accept: "text/html" } })
    .then(async (response) => {
      if (response.type === "opaqueredirect") {
        if (redirected.current) return redirected.current(); // onRedirect
        throw new Error("redirected");
      }
      const isFragment =
        (response.ok || response.status === 500) &&
        (response.headers.get("content-type") ?? "").startsWith("text/html");
      if (!isFragment) throw new Error(`HTTP ${response.status}`);
      const template = document.createElement("template");
      template.innerHTML = await response.text();
      target.replaceChildren(template.content); // the element upgrades on insert
    });
  return () => target.replaceChildren();
}, [id, search]);

// ShopClientDroplet: the element alone; it fetches its own data.
const element = document.createElement(SHOP_ELEMENT); // "djs-shop"
element.dataset["droplet"] = id;
element.dataset["params"] = paramsKey; // JSON.stringify(params)
target.replaceChildren(element);
```

```nginx
# nginx.conf
location ~ ^/(index\.js$|droplets/|assets/|api/) {
  proxy_pass http://shop:8300;
  proxy_set_header x-droplet-location ${SHOP_PUBLIC_URL};
}
location / {
  try_files $uri /index.html;
}
```

- `ShopFragment` fetches `GET /droplets/<id>?<query>` from the browser with
  `accept: text/html`. It is a same-origin request, so the browser sends the
  shop's cookies and the page's URL as `Referer` itself, and nginx adds
  `x-droplet-location` on the way to the shop. `redirect: "manual"` turns a
  3xx into an `opaqueredirect`, which the page handles (`onRedirect`).
- Only a `text/html` answer (a 2xx, or a 500 carrying the droplet's error
  page) is inserted, through a `<template>`; anything else shows as unavailable.
- `ShopClientDroplet` writes `<djs-shop data-droplet="…" data-params="…">`
  instead: nothing server-rendered, the element fetches its data once its
  bundle has loaded.
- `ensureShopClient()` adds `<script type="module" src="/index.js">` to the
  head once. `nginx.conf` passes `/index.js`, `/droplets/*`, `/assets/*` and
  `/api/*` to the shop and answers every other path with `index.html`; it is
  a template, and the nginx image fills in `${SHOP_PUBLIC_URL}`
  (`http://localhost:8004`) when it starts.

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8004, public | nginx serving the built app (`index.html` for every route) and proxying the shop |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, public | the Svelte example's droplets server, for `/` only (`VITE_DROPLETS_URL` at build) |

There is no server code. `nginx.conf` writes out the shop's internal address
(`proxy_pass http://shop:8300`); it is a template (the nginx image's
`/etc/nginx/templates/`), so the public one, `x-droplet-location ${SHOP_PUBLIC_URL}`,
comes from `SHOP_PUBLIC_URL` (`http://localhost:8004`) at start. Under `vite dev` and `vite preview`,
`server.proxy` does the same from `SHOP_INTERNAL_URL` and `SHOP_PUBLIC_URL`.

### How a page gets a droplet

Client-only. The pages fetch each fragment from the browser, through the
proxy, and insert it; the element upgrades and hydrates itself. The code is
`ShopFragment`, shown in the pattern above.

The browser sends the shop's cookies and the page's URL as `Referer` itself:
same origin. The cart badge is client-only: a
`<djs-shop data-droplet="shopping-cart">` the app writes, which fetches
its own data. So are the toasts, first in the layout and kept across
client-side navigations; `/index.js` installs `window.shopMessageQueue`
before any droplet starts (the shop's `src/hooks.client.ts`):

```tsx
// src/shop/ShopApp.tsx
<ShopClientDroplet id="toast-center" params={{}} />
<header className="shop-header">…<ShopClientDroplet id="shopping-cart" params={{ variant: "badge" }} />…</header>
```

### What it proxies

`location ~ ^/(index\.js$|droplets/|assets/|api/)` in `nginx.conf` passes
`/index.js`, `/droplets/*` (fragments, `_data`, form actions), `/assets/*`
and `/api/*` to the shop with `x-droplet-location` written out and
`Forwarded`/`X-Forwarded-*` cleared (the shop reads them only as a fallback
for its location, and trusts them only against its allow-list). Every
request the page makes is same-origin: no CORS, and the shop's cookies are
the app's own. Login and the other forms are full-page posts through the
proxy, so the shop's `303` and `Set-Cookie` reach the browser as they are.

### The shop's environment

- `DROPLETS_TRUSTED_ORIGINS: http://localhost:8004`: the only origin whose
  [`x-droplet-location`](/integrate/http-contract/#x-droplet-location-the-public-location) and
  [form posts](/integrate/http-contract/#form-posts-the-origin-check) the shop accepts.
- `DROPLETS_SECRET`: signs a form's result on the redirect back to the page
  when JavaScript is off ([Post/Redirect/Get](/integrate/http-contract/#postredirectget));
  this host has no such path (below), the others do.
- `ADMIN_USER`, `ADMIN_PASSWORD`, `SHOP_SECRET`: the demo login
  (admin / droplets) and the key its cookie is signed with. Demo values only.

### Gotchas

- **No server rendering, no no-JS path.** The pages render in the browser,
  so nothing shows before the bundle runs, and a post without JavaScript has
  no page to land back on: the end-to-end test skips that run here.
- **The app's own files live under `/app/`** (`build.assetsDir: "app"`), so
  `/assets/*` stays the shop's.
- **Redirects are opaque in the browser.** With `redirect: "manual"`, a
  fragment's 3xx has no readable target, so the product page replaces its
  URL without `v` itself.

## The Svelte example

The app's `/` is the Svelte example: its three droplets, one per mode, from `examples/frameworks/svelte` (the `droplets` service, at `VITE_DROPLETS_URL`).

A single-page app has no server of its own, so it cannot paste fragments in
before the page ships. The example wraps a droplet in a React component with
two modes.

**`fragment`** (default) fetches `GET /droplets/<id>` from the browser and inserts
the server-rendered HTML. The droplet's own JavaScript then hydrates it. Good
for content that should be visible as soon as possible.

**`client`** renders the droplet element (the server's `element` setting,
`djs-svelte` for the Svelte example) with `data-droplet` and the
props directly. It loads from where `/index.js` came from. The element runs the droplet's
loads in the browser, fetching `/droplets/<id>/_data` when it has a server
load, and mounts the component. Nothing shows until the bundle loads.

```tsx
const DROPLETS_URL = import.meta.env.VITE_DROPLETS_URL ?? "http://localhost:8000";
const DROPLETS_ELEMENT = import.meta.env.VITE_DROPLETS_ELEMENT ?? "djs-svelte";

export function Droplet({ id, props = {}, mode = "fragment" }: DropletProps) {
  const host = useRef<HTMLDivElement>(null);

  useEffect(() => {
    ensureDropletsClient();                 // adds /index.js once per page
    const target = host.current!;

    if (mode === "client") {
      const element = document.createElement(DROPLETS_ELEMENT);
      element.dataset.droplet = id;
      element.dataset.context = encodeContext(props);   // base64 { props }; or data-params='{"who":"Ana"}'
      target.replaceChildren(element);
      return () => target.replaceChildren();
    }

    const url = new URL(`/droplets/${id}`, DROPLETS_URL);
    for (const [k, v] of Object.entries(props)) url.searchParams.set(k, String(v));
    fetch(url, { redirect: "manual" }).then(async (response) => {
      // Only an HTML answer is a fragment (a 500 carries the error page); a
      // 400 or 404 is text that may echo the props: never insert it as HTML.
      const isFragment = (response.ok || response.status === 500) &&
        (response.headers.get("content-type") ?? "").startsWith("text/html");
      if (!isFragment) return console.error(`${id}: ${response.status}`);
      const template = document.createElement("template");
      template.innerHTML = await response.text();
      target.replaceChildren(template.content);   // the element upgrades on insert
    });
    return () => target.replaceChildren();
  }, [id, mode, JSON.stringify(props)]);

  return <div ref={host} />;
}
```

```tsx
{["ssr-hydrate", "ssr-nohydrate"].map((id) => (
  <Droplet key={id} id={id} props={{ who }} />
))}
<Droplet id="client" mode="client" />
```

React owns the wrapper `<div>`; the custom element owns everything inside it.
The effect's cleanup clears the wrapper, so React never tries to reconcile the
droplet's DOM.

The full component, with error handling, is `examples/hosts/react-vite/src/droplets.tsx`.
The page and the droplets server are different origins, so the droplets server
runs with `cors: true`.
