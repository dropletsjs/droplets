How an ASP.NET Core app embeds droplets: a Razor page model fetches each
fragment with an `HttpClient` from `IHttpClientFactory`, and the Razor page
prints it with `Html.Raw`.

## The pattern in ASP.NET Core

```csharp
// src/HostApp.cs (trimmed): one handler for every visitor, so it keeps no cookies
builder.Services.AddHttpClient(ShopClient, client => client.Timeout = TimeSpan.FromSeconds(10))
    .ConfigurePrimaryHttpMessageHandler(() =>
        new SocketsHttpHandler { UseCookies = false, AllowAutoRedirect = false, AutomaticDecompression = DecompressionMethods.None });
```

```csharp
// src/Shop/ShopFragments.cs (trimmed)
public async Task<Fragment> Get(HttpContext context, Wanted wanted)
{
    var url = $"{settings.ShopInternalUrl}/droplets/{Uri.EscapeDataString(wanted.Droplet)}?{ShopRequest.BuildQuery(wanted.Props)}";
    using var request = new HttpRequestMessage(HttpMethod.Get, url);
    request.Headers.TryAddWithoutValidation("accept", "text/html");
    request.Headers.TryAddWithoutValidation("x-droplet-location", settings.ShopOrigin);
    request.Headers.TryAddWithoutValidation("referer", settings.ShopOrigin + ShopRequest.RawTarget(context));
    var cookie = ShopRequest.ShopCookie(context.Request.Headers.Cookie);
    if (cookie is not null) request.Headers.TryAddWithoutValidation("cookie", cookie);

    using var response = await clients.CreateClient(HostApp.ShopClient).SendAsync(request, context.RequestAborted);
    var status = (int)response.StatusCode;
    var cookies = response.Headers.TryGetValues("set-cookie", out var setCookies) ? setCookies.ToArray() : [];
    var isHtml = response.Content.Headers.ContentType?.MediaType == "text/html";
    if (status is >= 300 and < 400) location = response.Headers.Location?.OriginalString;
    else if ((response.IsSuccessStatusCode || status is 500 or 504) && isHtml)
        return new Fragment(await response.Content.ReadAsStringAsync(context.RequestAborted), status, null, cookies, link);
    // … anything else: a "droplet is unavailable" note, the id HTML-encoded
}
```

```razor
@* src/Pages/Shared/_ShopLayout.cshtml, in <head>: once per page *@
<script type="module" src="/index.js"></script>
@* src/Pages/Gallery.cshtml: the fragment's HTML, as it came *@
<aside>@Html.Raw(Model.Fragments[0])</aside>
```

- `ShopFragments.Get` sends `GET /droplets/<id>?<params>` to
  `SHOP_INTERNAL_URL` with `accept: text/html` and `x-droplet-location` set
  to `ShopOrigin`, the origin of `SHOP_PUBLIC_URL`, read from configuration
  in `HostSettings.cs`. It passes on the browser's `Cookie` cut down to the
  shop's own `cart_id` and `shop_admin`, and the page's URL as `referer`:
  `ShopOrigin` plus the path and query as the browser sent them
  (`IHttpRequestFeature.RawTarget`).
- The named client comes from `IHttpClientFactory`, whose pooled handler
  never follows a redirect (`AllowAutoRedirect = false`), so a droplet's 3xx
  is answered as it is, and never keeps a cookie (`UseCookies = false`).
  `ShopPage.Render` sends the fragments' `Set-Cookie` with the page; a
  fragment's redirect answers the whole page with that status and
  `Location`.
- Only a `text/html` answer (a 2xx, or a 500 or 504 carrying the droplet's error
  page) is printed with `Html.Raw`; Razor encodes everything else.
- `_ShopLayout.cshtml` loads `/index.js` once. Minimal API endpoints
  (`MapMethods`) pass `/index.js`, `/env.js`, `/index.css`, `/droplets/*`,
  `/assets/*` and `/api/*` on to the shop.

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8014, public | ASP.NET Core on Kestrel: the shop's pages, the proxy, and the basic page at `/` |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, public | the Svelte example's droplets server, for `/` only |

| On `web` | Value | Used for |
| --- | --- | --- |
| `SHOP_INTERNAL_URL` | `http://shop:8300` | internal: fragment fetches and the proxy |
| `SHOP_PUBLIC_URL` | `http://localhost:8014` | public: this host's own origin, sent as `x-droplet-location` |
| `DROPLETS_INTERNAL_URL`, `DROPLETS_PUBLIC_URL` | `http://droplets:8000`, `http://localhost:8000` | the same pair, for the basic page |

ASP.NET Core's configuration reads them from the environment, so
`appsettings.json` or command-line arguments set them as well.

### How a page gets a droplet

Each shop page is a Razor page whose model derives from `ShopPage`. Its
`OnGet` names the droplets it needs, and `Render` fetches them together
with the toasts and the header's cart badge, all at once (`Task.WhenAll`):

```csharp
// src/Pages/Product.cshtml.cs
public async Task<IActionResult> OnGet(string slug)
{
    Product = await Shop.Product(slug, HttpContext.RequestAborted);
    if (Product is null) return await Render("Not found", null, [], StatusCodes.Status404NotFound);
    var query = PageQuery;
    List<Pair> comments = [.. ShopRequest.Pick(query, "order", "page", "showing"), new Pair("productId", Product.Id)];
    List<Pair> page = [new Pair("slug", Product.Slug), .. ShopRequest.Pick(query, "v")];
    return await Render(Product.Name, null, [new Wanted("product-page", page), new Wanted("product-comments", comments)]);
}
```

```csharp
// src/Pages/ShopPage.cs (trimmed)
var results = await shop.GetAll(
    HttpContext,
    [new Wanted("toast-center", []), new Wanted("shopping-cart", [new Pair("variant", "badge")]), .. wanted]);
Response.Headers.CacheControl = "private, no-store";
foreach (var cookie in results.SelectMany(result => result.Cookies)) Response.Headers.Append("set-cookie", cookie);
var redirect = results.FirstOrDefault(result => result.Location is not null);
if (redirect is not null)
{
    Response.Headers.Location = redirect.Location;
    return StatusCode(redirect.Status);
}
```

`referer` is the page's URL, query included. The shop's `handle` reads it
with `hostFrom`, so it is the droplet's
[`host`](/integrate/http-contract/#host-where-the-droplet-renders), and after
a form posted without JavaScript its query carries the form's result. The
layout puts the `toast-center` fragment first in the body, and `/index.js`
installs `window.shopMessageQueue` before any droplet starts (the shop's
`src/hooks.client.ts`):

```razor
@* src/Pages/Shared/_ShopLayout.cshtml *@
<body class="shop">
@Html.Raw(Model.Toasts)
<header class="shop-header">…<div class="shop-cart">@Html.Raw(Model.Cart)</div>…</header>
```

The product page first reads the product from the shop's public
`GET /droplets/product-page/_data?slug=<slug>`; an unknown slug renders
"Not found" with `404`. The pages read their query in order, repeated keys
kept, and pass on only the keys each droplet takes: the whole query to
`product-filter` and `product-library`, `order`, `page` and `showing` (plus
`productId`) to `product-comments`, `slug` and `v` to `product-page`,
`next` to `login`, `view` and `id` to `product-admin`. The fragments'
`Link` preloads on the shop's origin go into `<head>`.

### What it proxies

```csharp
// src/Shop/ShopProxy.cs (trimmed)
private static readonly string[] Methods = ["GET", "HEAD", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"];
private static readonly string[] Routes = ["/index.js", "/env.js", "/index.css", "/droplets/{**rest}", "/assets/{**rest}", "/api/{**rest}"];

public static void MapShopProxy(this IEndpointRouteBuilder app)
{
    foreach (var route in Routes) app.MapMethods(route, Methods, Proxy);
}

private static async Task Proxy(HttpContext context, IHttpClientFactory clients, HostSettings settings, ILoggerFactory logs)
{
    var target = ShopRequest.RawTarget(context);
    if (!ShopRequest.IsShopPath(target))
    {
        await Plain(context, StatusCodes.Status400BadRequest, "Bad request.");
        return;
    }
    using var request = new HttpRequestMessage(new HttpMethod(context.Request.Method), settings.ShopInternalUrl + target);
    request.Headers.TryAddWithoutValidation("x-droplet-location", settings.ShopOrigin);
    …
}
```

`Proxy` covers `/index.js`, `/env.js`, `/index.css`, `/droplets/*`
(fragments, `_data`, form actions), `/assets/*` and `/api/*`. It sends the
shop `x-droplet-location` written out and only these of the browser's
headers: `accept`, `accept-language`, `content-type`, `if-none-match`,
`origin`, `referer`, `user-agent`, `x-droplet-props` and `x-droplets-build`,
plus `cookie` cut down to the shop's own `cart_id` and `shop_admin`, so
another app's cookie on this origin stays here. The target is the raw path
and query concatenated onto `SHOP_INTERNAL_URL`, never resolved, so
`//elsewhere` stays a path on the shop; a target that is not a path, or has
a `.` or `..` segment once decoded, is refused with `400` (Kestrel removes
dot segments before routing, so the check reads the raw target). A request
body is read into memory up to 4 MB and refused with `413` above it, before
the shop is asked; the answer is streamed back
(`HttpCompletionOption.ResponseHeadersRead`) with its status, every
`Set-Cookie` and any redirect, without the per-hop headers and
`content-length`. A shop that cannot be reached answers `502`
`The shop is unreachable.`

The shop's cookies (`cart_id`, `shop_admin`) are first-party, and nothing
is cross-origin; the shop sets them only from form actions and `/api`,
which come through here.

### Gotchas

- **The handler must not keep cookies.** `IHttpClientFactory` pools one
  `SocketsHttpHandler` for every visitor, and its default `CookieContainer`
  would store the first visitor's `cart_id` (or admin session) from a
  proxied answer and send it with everyone else's requests.
  `UseCookies = false` turns it off; what goes out is the browser's own
  `Cookie`, cut down to `cart_id` and `shop_admin`.
- **`Html.Raw` only for the shop's HTML.** Razor encodes everything else;
  the "unavailable" note is built with `HtmlEncoder.Default`, so the
  droplet's id is encoded. See [For hosts](/guides/security/#for-hosts).
- **The raw target, not `Request.Path`.** The `referer` and the proxied URL
  use `IHttpRequestFeature.RawTarget`, the path and query exactly as the
  browser sent them: `Request.Path` is decoded and has its dot segments
  removed.
- **The page is `private, no-store`.** `Render` sets it on every shop page
  and redirect: their fragments were rendered with the visitor's cookies.

### Tests

`test/` runs the app on Kestrel on a free loopback port, with the shop's
`HttpClient` handler replaced by a fake that records what it is sent. The
tests check that `x-droplet-location` is the configured origin when the
request names another `Host`, `X-Forwarded-Host` or `Forwarded`, that only
the listed headers and the shop's cookies go on, that dot segments
(`..`, `%2e%2e`) and a body over 4 MB never reach the shop, and that a
non-HTML answer is never inserted into a page. The image's build runs them
(`dotnet test`) before it publishes.

### Run it

```bash
cd examples/hosts/aspnet
docker compose up --build
open http://localhost:8014/gallery   # log in as admin / droplets
```

Set `SHOP_SECRET` and `DROPLETS_SECRET` first; compose refuses to start
without them. The shop trusts one origin besides its own,
`DROPLETS_TRUSTED_ORIGINS: http://localhost:8014`, this host's; the rest of
its environment is the same on every host: see
[Running a host](/integrate/hosts/shop-demo/#running-a-host).

## The Svelte example

The same app serves the Svelte example at `/`: its three droplets, one per
mode, from `examples/frameworks/svelte` (the `droplets` service). No
JavaScript runs on the host: C# fetches the fragments and a Razor page
prints them.

```csharp
// src/Pages/Index.cshtml.cs (trimmed)
private static readonly string[] Ids = ["client", "ssr-hydrate", "ssr-nohydrate"];

public async Task OnGet(string who = "ASP.NET Core")
{
    Fragments = await Task.WhenAll(Ids.Select(id => Fetch(id, [new Pair("who", who)])));
}

private async Task<string> Fetch(string droplet, IReadOnlyList<Pair> props)
{
    var url = $"{settings.DropletsInternalUrl}/droplets/{Uri.EscapeDataString(droplet)}?{ShopRequest.BuildQuery(props)}";
    using var request = new HttpRequestMessage(HttpMethod.Get, url);
    request.Headers.TryAddWithoutValidation("accept", "text/html");
    request.Headers.TryAddWithoutValidation("x-droplet-location", settings.DropletsPublicUrl);
    try
    {
        using var response = await clients.CreateClient(HostApp.DropletsClient).SendAsync(request, HttpContext.RequestAborted);
        // Only an HTML answer is a fragment (a 500 or 504 carries the droplet's
        // error page); anything else may echo the props, so it is never pasted.
        var isHtml = response.Content.Headers.ContentType?.MediaType == "text/html";
        if ((response.IsSuccessStatusCode || (int)response.StatusCode is 500 or 504) && isHtml)
        {
            return await response.Content.ReadAsStringAsync(HttpContext.RequestAborted);
        }
        return $"<p class=\"error\">droplet \"{HtmlEncoder.Default.Encode(droplet)}\" unavailable: HTTP {(int)response.StatusCode}</p>";
    }
    catch (Exception error) when (error is HttpRequestException or TaskCanceledException)
    {
        // The error names the internal URL: it goes to the log, not the page.
        logger.LogError(error, "{Droplet}: the droplets server is unreachable", droplet);
        return $"<p class=\"error\">droplet \"{HtmlEncoder.Default.Encode(droplet)}\" unavailable</p>";
    }
}
```

```razor
@* src/Pages/Index.cshtml *@
<script type="module" src="@Model.DropletsPublicUrl/index.js"></script>
…
@foreach (var fragment in Model.Fragments)
{
  @Html.Raw(fragment)
}
```

Only a `text/html` answer is printed with `Html.Raw` (a 2xx, or a 500 or
504 carrying the droplet's error page); any other answer prints an error
paragraph with its status, the id encoded. A failed request prints a fixed
one and logs the error, since its message names the internal URL. Here the
page loads `/index.js` from the droplets server's public URL, another
origin than the page, so the Svelte example runs with `cors: true` and
`DROPLETS_TRUSTED_ORIGINS` lists both `DROPLETS_URL` and this host's
`WEB_URL`. The same fetch works from an MVC controller and its view, or a minimal
API endpoint: anything in .NET that can make an HTTP request and print a
string.
