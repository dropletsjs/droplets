How nginx embeds droplets with no application code: an SSI include fetches
each fragment while nginx serves the page, and a reverse proxy carries the rest.

## The pattern in nginx

```nginx
# nginx.conf, the shop's server block (trimmed)
location = /gallery {
  ssi on;
  rewrite ^ /gallery.html break;
}

# What the browser asks the shop for.
location ~ ^/(index\.js|droplets/|assets/|api/) {
  proxy_pass http://shop;
  proxy_set_header x-droplet-location "";
  proxy_set_header Forwarded "";
  proxy_set_header X-Forwarded-Host "";
  proxy_set_header X-Forwarded-Proto "";
  proxy_set_header X-Forwarded-Prefix "";
}

# The fragments the pages include.
location ^~ /_fragment/ {
  internal;
  rewrite ^/_fragment(/.*)$ $1 break;
  proxy_pass http://shop;
  proxy_set_header Referer ${SHOP_PUBLIC_URL}$request_uri;
  proxy_set_header Accept text/html;
  proxy_intercept_errors on;
  error_page 400 401 403 404 405 413 431 502 503 504 = @unavailable;
}
```

```html
<!-- shop/_layout/head.html: one script per page, through the proxy -->
<script type="module" src="/index.js"></script>
<!-- shop/gallery.html -->
<aside><!--# include virtual="/_fragment/droplets/product-filter?$args" --></aside>
```

- `ssi on` makes nginx run the page's `include virtual` while it serves
  `/gallery`. The include is a subrequest to `/_fragment/droplets/product-filter`,
  which `/_fragment/` rewrites to `GET /droplets/product-filter?<the page's query>`
  on the shop, with `Accept: text/html`, the page's URL as `Referer`, and the browser's `Cookie`, which a
  subrequest carries. nginx does not follow the answer's redirect.
- The answer's body goes into the page where the include was. The error
  statuses listed in `error_page` become a fixed note
  (`<p class="shop-unavailable">This droplet is unavailable.</p>`), so only a
  2xx, or a 500 with the droplet's error page, is pasted.
- `nginx.conf` is a template: the nginx image fills in `${SHOP_PUBLIC_URL}`
  (`http://localhost:8081`) when it starts.
- The `location ~` block passes `/index.js`, `/droplets/*`, `/assets/*` and
  `/api/*` to the shop, so the browser only talks to nginx.
- nginx sends no location header. The shop knows its public URL from
  `DROPLETS_ORIGIN=http://localhost:8081` and writes every fragment's URLs on
  it. The headers a client could name another location with
  (`x-droplet-location`, `Forwarded`, `X-Forwarded-*`) are cleared: the shop
  would trust them only against that list anyway.

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8081 (the shop) and 8080 (the basic page), public | `nginx:1.27-alpine` with `nginx.conf`, `shop/` and `html/` copied in (its `Dockerfile`) |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, internal only | the Svelte example's droplets server, behind port 8080 |

The internal addresses are `upstream` blocks (`server shop:8300;`). The
public ones are in two places: each droplets server's `DROPLETS_ORIGIN`
(`http://localhost:8081` for `shop`, `http://localhost:8080` for `droplets`),
and `web`'s `SHOP_PUBLIC_URL`, which fills in the `Referer` of
`/_fragment/` (`nginx.conf` is a template, the nginx image's
`/etc/nginx/templates/`). The shop has its own
port because its `/index.js` and `/droplets/*` would collide with the basic
server's on 8080.

### How a page gets a droplet

Server Side Includes. Each page is an `.html` file of SSI directives; every
include goes through one internal location that sets the headers: the
`/_fragment/` block in the pattern above.

A subrequest carries the browser's `Cookie`, so the cart badge and the admin
render for the visitor. `Referer` is the page's URL: the droplet's
[`host`](/integrate/http-contract/#host-where-the-droplet-renders). The shared
`<head>` (`shop/_layout/head.html`) loads `<script type="module" src="/index.js">`
once, through the proxy, and each droplet hydrates itself. The shared header
(`shop/_layout/header.html`, included right after `<body>` on every page)
starts with the toasts; `/index.js` installs `window.shopMessageQueue` before
any droplet starts (the shop's `src/hooks.client.ts`):

```html
<!--# include virtual="/_fragment/droplets/toast-center" -->
<header class="shop-header">…<!--# include virtual="/_fragment/droplets/shopping-cart?variant=badge" -->…</header>
```

### What it proxies

`location ~ ^/(index\.js|droplets/|assets/|api/)` passes `/index.js`,
`/droplets/*` (fragments, `_data`, form actions), `/assets/*` and `/api/*`
to the shop with `x-droplet-location`, `Forwarded` and `X-Forwarded-*`
cleared. Bodies, `Set-Cookie` and `303`s pass through as they are, so the
cart and the login cookies are first-party, and nothing is cross-origin.
`client_max_body_size 4m` lets the admin's image uploads through.

### The shop's environment

- `DROPLETS_ORIGIN: http://localhost:8081`: the shop's
  [public location](/integrate/http-contract/#x-droplet-location-the-public-location),
  where it writes its URLs and the only origin whose
  [form posts](/integrate/http-contract/#form-posts-the-origin-check) it accepts.
- `DROPLETS_SECRET`: signs a form's result on the redirect back to the page
  when JavaScript is off ([Post/Redirect/Get](/integrate/http-contract/#postredirectget)).
- `ADMIN_USER`, `ADMIN_PASSWORD`, `SHOP_SECRET`: the demo login
  (admin / droplets) and the key its cookie is signed with. Demo values only.

### Gotchas

- **SSI drops a fragment's headers.** An `include virtual` is a subrequest:
  nginx copies its body into the page and discards its `Set-Cookie`, its
  `Link` preloads and its redirect. The shop is fine with that, since it sets
  cookies only from form actions and `/api`, which go through the proxy. A
  droplet that sets a cookie or redirects on a plain `GET` cannot be
  composed with SSI: render that page in code (njs, OpenResty, or another
  host on this list).
- **The product page asks first.** An `auth_request` to the product
  fragment turns an unknown slug into a 404 and an old `v` into a 302 from
  nginx, since SSI could not pass the fragment's redirect on. The product's
  name and id come from its `_data` read into an SSI variable
  (`subrequest_output_buffer_size 64k`).

## The Svelte example

Port 8080 serves the Svelte example: its three droplets, one per mode, from `examples/frameworks/svelte` (the `droplets` service), with the same two tools.

The host is a static `index.html`. nginx does two things:

- **Server Side Includes.** `<!--# include virtual="/droplets/ssr-hydrate?who=nginx" -->`
  makes nginx fetch the fragment while serving the page, so the browser
  receives server-rendered markup.
- **Reverse proxy.** The droplets routes are proxied under nginx's own origin.
  The browser only ever talks to nginx, so the droplets server needs no CORS,
  and `DROPLETS_ORIGIN` tells it to write the fragments' URLs on nginx's origin. Droplets build
  their API calls from that origin ([`$droplets/drop`](/reference/api/#dropletsdrop)),
  so `/api/*` goes through the proxy too.

### The page

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Droplets in nginx</title>
  <script type="module" src="/index.js"></script>
</head>
<body>
  <!--# include virtual="/droplets/client?who=nginx" -->
  <!--# include virtual="/droplets/ssr-hydrate?who=nginx" -->
  <!--# include virtual="/droplets/ssr-nohydrate?who=nginx" -->
</body>
</html>
```

### The configuration

```nginx
upstream droplets {
  server droplets:8000;
}

server {
  listen 80;
  root /usr/share/nginx/html;

  # Static pages with <!--# include virtual="/droplets/<id>" --> directives.
  location / {
    ssi on;
    try_files $uri $uri/ =404;
  }

  # Everything the droplets server owns: the entry client, the droplet routes
  # (fragments, bundles, styles, _data), the shared assets and its /api
  # endpoints.
  location ~ ^/(index\.js|droplets/|assets/|api/) {
    proxy_pass http://droplets;
    proxy_set_header x-droplet-location "";
    proxy_set_header Forwarded "";
    proxy_set_header X-Forwarded-Host "";
    proxy_set_header X-Forwarded-Proto "";
    proxy_set_header X-Forwarded-Prefix "";
  }
}
```

nginx says nothing about where it is: the droplets server has the site's
public URL in its environment, and with that one entry it needs no header.

```yaml
# docker-compose.yml
droplets:
  environment:
    DROPLETS_ORIGIN: http://localhost:8080
```

The `proxy_set_header` lines clear what a client may have sent. The
droplets server would only trust a location header whose origin is in
`DROPLETS_ORIGIN` (or `trustedOrigins`) anyway; clearing them keeps the
warnings out of its log.

Behind a path (`location /mfe/`), put the path in it:
`DROPLETS_ORIGIN=https://shop.example/mfe`. With several public URLs (one
server for `shop.example` and `www.shop.example`), list them all and let
nginx say which one the request came through, with the path:

```nginx
location /mfe/ {
  proxy_pass http://droplets/;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-Host $host;
  proxy_set_header X-Forwarded-Prefix /mfe;
}
```

```bash
DROPLETS_ORIGIN=https://shop.example,https://www.shop.example
```

`$host` comes from the client's `Host` header, so it is only used when it
is one of the listed origins; any other falls back to the request's own
origin, with a warning.

Run it from the repository: `cd examples/hosts/nginx && docker compose up --build`,
then open `http://localhost:8080`.

## IIS

`examples/hosts/nginx/iis/web.config` is the equivalent URL Rewrite + Application
Request Routing (ARR) reverse-proxy configuration. It has **not** been run on
a Windows host; treat it as a starting point. Two notes:

- Enable "proxy" in ARR's server settings, and allow the `HTTP_X_HOST` server
  variable in `applicationHost.config` so the rewrite rule can set it. Set it
  to the site's public URL, written out, never to a value built from the
  request's `Host`.
- IIS cannot include arbitrary URLs server-side. Pair it with a page that
  fetches fragments itself (an ASP.NET page following the
  [Express](/integrate/hosts/express/) pattern) or with the client-only pattern from
  the [React example](/integrate/hosts/react-vite/).
