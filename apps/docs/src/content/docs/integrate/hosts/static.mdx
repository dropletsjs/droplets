How a plain HTML file embeds droplets with nothing behind it but a file
server: the page loads the droplets server's `/index.js`, fetches each
fragment from the browser and inserts it. The droplets server stays on its
own origin; nothing is proxied. This is the
[client-only page](/integrate/client-only/) at its smallest, and what a page
on any static host (an object store, a CDN, GitHub Pages) does.

## The pattern in plain HTML

```html
<!-- html/index.html (trimmed) -->
<head>
  <link rel="stylesheet" href="/shop.css">
  <script type="module" src="http://localhost:8000/index.js"></script>
  <script type="module" src="/shop.js"></script>
</head>
<body class="shop">
  <djs-shop data-droplet="toast-center"></djs-shop>
  <header class="shop-header">
    …
    <div class="shop-cart"><djs-shop data-droplet="shopping-cart" data-droplet-props='{"variant":"badge"}'></djs-shop></div>
  </header>
  <main class="shop-main shop-wrap" id="page">…</main>
</body>
```

```js
// html/shop.js (trimmed)
const entry = [...document.querySelectorAll('script[type="module"][src]')]
  .map((script) => new URL(script.src))
  .find((url) => url.pathname.endsWith("/index.js"));
const DROPLETS = new URL(".", entry).href;

async function fragment({ id, params, target, onRedirect }) {
  const response = await fetch(new URL(`droplets/${encodeURIComponent(id)}?${params}`, DROPLETS), {
    redirect: "manual",
    headers: { accept: "text/html" },
    credentials: "include",
    referrerPolicy: "no-referrer-when-downgrade",
  });
  if (response.type === "opaqueredirect" && onRedirect) return onRedirect();
  const isFragment =
    (response.ok || [500, 504].includes(response.status)) && (response.headers.get("content-type") ?? "").startsWith("text/html");
  if (!isFragment) throw new Error(`HTTP ${response.status}`);
  const template = document.createElement("template");
  template.innerHTML = await response.text();
  target.replaceChildren(template.content);
}
```

- `/index.js` comes from the droplets server and defines its element
  (`djs-shop`, the shop's `element`). Every droplet then loads its bundle,
  stylesheet and data from where `/index.js` came from, so `shop.js` reads
  the server's URL from that one tag.
- `shop.js` asks for each fragment with `fetch` and inserts it through a
  `<template>`, so the element upgrades as it enters the document and
  hydrates as its droplet says. It inserts an HTML answer only (a `2xx`, or
  a `500` or `504` carrying the droplet's error page); anything else shows a fixed
  note, since its text may echo the props.
- `credentials: "include"` sends the shop's cookies (the cart, the admin
  session) and keeps the ones it sets; the referrer policy sends the
  page's whole URL as `Referer`, where the shop takes the host page from
  (a form's result comes back to it).
- The toasts and the cart badge are elements the page writes itself:
  `toast-center` and `shopping-cart` are client only and render in the
  browser.
- The request goes from the browser straight to the droplets server, so the
  fragment's URLs are on that server's own origin and no
  `x-droplet-location` is involved.

## The static page, recorded

by the end-to-end test (`tests/hosts/e2e/shop.spec.ts`, as on every shop
host): products into the cart, a product page, the admin's login, a stock
set to 0, and the cart and the product page saying so.

The code is in `examples/hosts/static`: `html/index.html`, `html/shop.js`,

`nginx.conf` and the `Dockerfile`.

### Pieces and ports

`docker-compose.yml` starts two services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8011, on `127.0.0.1` | `nginx:1.27-alpine` serving the page and its files; it proxies nothing |
| `shop` | 8000, on `127.0.0.1` | the shop's droplets server (`examples/shop`), which the browser asks directly, cross-origin |

| Path | What `shop.js` asks for |
| --- | --- |
| `/gallery` | `product-filter` and `product-library`, with the page's whole query (the shop drops what a droplet does not take) |
| `/product/<slug>` | the product's id, name and category from `GET /droplets/product-page/_data?slug=`, then `product-page` (`slug`, and `v` when the link has one) and `product-comments` (the id; `order`, `page`, `showing`) |
| `/admin` | `product-admin` (`view`, `id`) |
| `/login` | `login` (`next`) |

nginx answers these paths with the same `index.html`, and only a slug of the
shop's shape (`[a-z0-9]+(?:-[a-z0-9]+)*`) gets it; `/` redirects to
`/gallery`. The page names its droplets server as `http://localhost:8000`;
when it is published elsewhere, `sub_filter` in `nginx.conf` rewrites that
URL to `DROPLETS_PUBLIC_URL`.

The shop's links are root-relative (`/product/<slug>?v=…`), so they land on
this page's origin, which answers them with the same file. An old `v` answers
a redirect, opaque to a cross-origin `fetch`: `shop.js` drops `v` from the
page's URL and asks again, and the product renders live.

### The droplets server's side

The shop's `droplets.config.ts` answers the origins listed in
`DROPLETS_TRUSTED_ORIGINS` by name, with credentials, and any other origin
with no CORS headers:

```ts
// examples/shop/droplets.config.ts (trimmed)
function trustedHostOrigins(): string[] {
  return (process.env.DROPLETS_TRUSTED_ORIGINS ?? "")
    .split(",")
    .map((entry) => entry.trim())
    .filter((entry) => entry !== "" && entry !== "*");
}

export default config({
  cors: {
    origin: (origin) => (trustedHostOrigins().includes(origin) ? origin : null),
    credentials: true,
  },
});
```

- `DROPLETS_TRUSTED_ORIGINS` lists this page's origin
  (`http://localhost:8011`), so the same list trusts its form posts and
  redirects and lets it read the answers with cookies. It is read per
  request: a new page needs no rebuild. `*` is skipped: a credentialed
  answer never allows any origin.
- With `credentials` in `cors`, the element's own requests (the enhanced
  form posts, `_data`, a fragment rendered again after a post) include the
  cookies too ([Cookies across origins](/guides/security/#cookies-across-origins)),
  and the shop's own `/api` calls already do. So the cart, the admin, the
  filter's refresh in place and the comments work as on the proxied hosts.
- The login is a plain form post to the shop, a navigation: its cookie is
  set there, and its 303 lands on this page's `/admin`.
- A `GET` with only an `Accept` header needs no preflight; a JSON `POST`
  (`_data`, the cart's stock check) does, and `cors` answers it.

### Run it

```bash
cd examples/hosts/static
docker compose up --build
open http://localhost:8011/gallery
```

Set `SHOP_SECRET` and `DROPLETS_SECRET` first (32 or more random characters
each, `openssl rand -hex 32`), in the environment or a `.env` file beside
`docker-compose.yml`: compose refuses to start without them. `pnpm test:hosts`
generates its own for a run.

`pnpm test:hosts static` runs it end to end, from the repository root: the
shop flow, as on every shop host, and this page's own checks
(`tests/hosts/e2e/static.spec.ts`): a page loaded with a query directly, an
unknown product, an old `v`, the page without JavaScript, and the shop's
CORS answer, this page's origin with credentials and no other origin.

## Cookies across sites

The page (`localhost:8011`) and the shop (`localhost:8000`) differ only by
port: two origins, one site, so the shop's `SameSite=Lax` cookies go along.
The same holds for a page on `www.example.com` and droplets on
`drops.example.com`. A page on another site (a site builder's domain)
makes them third-party cookies: they need `SameSite=None; Secure`, which
the shop does not set, and Safari blocks them, Firefox partitions them and
Chrome lets the visitor block them
([Cookies across origins](/guides/security/#cookies-across-origins)).
There, serve the droplets routes under the page's origin instead (the
[React + Vite](/integrate/hosts/react-vite/) and [htmx](/integrate/hosts/htmx/)
hosts proxy them), or render the page on a server.

## What a page rendered in the browser gives up

Nothing is in the HTML until the script has run: no droplet shows without
JavaScript, a form has no page to come back to without it, and search
engines see the empty page. Where that matters, paste the fragments in on
a server ([Ways to use Droplets](/start/ways-to-use/)).
