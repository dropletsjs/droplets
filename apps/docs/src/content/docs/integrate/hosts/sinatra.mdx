How a Sinatra app embeds droplets: a route fetches each fragment with
`Net::HTTP` and an ERB view prints it into the page.

## The pattern in Sinatra

```ruby
# shop.rb (trimmed)
def shop_fragment(id, params = [])
  headers = { "accept" => "text/html", "x-droplet-location" => SHOP_ORIGIN, "referer" => SHOP_ORIGIN + shop_raw_target }
  cookie = shop_request_header("cookie")
  headers["cookie"] = cookie if cookie
  target = "/droplets/#{URI.encode_www_form_component(id)}?#{URI.encode_www_form(params)}"
  result = { html: "", status: 502, location: nil, cookies: [], link: nil }
  response = shop_request("GET", target, headers) # Net::HTTP to SHOP_INTERNAL_URL
  code = response.code.to_i
  result.merge!(status: code, cookies: response.get_fields("set-cookie") || [], link: response["link"])
  if (300..399).cover?(code)
    result[:location] = response["location"]
  elsif (response.is_a?(Net::HTTPSuccess) || code == 500) && response["content-type"].to_s.start_with?("text/html")
    result[:html] = response.body.to_s.force_encoding("UTF-8")
    return result
  end
  # … anything else: result[:html] becomes a "droplet is unavailable" note
  result
end
```

```erb
<%# views/shop/layout.erb, in <head>: once per page %>
<script type="module" src="/index.js"></script>
<%# views/shop/gallery.erb: the fragment's HTML, as it came %>
<aside><%= fragments[0] %></aside>
```

- `shop_fragment` sends `GET /droplets/<id>?<params>` to `SHOP_INTERNAL_URL`
  with `accept: text/html`, `x-droplet-location` set to this host's public origin
  (`SHOP_ORIGIN`, from `SHOP_PUBLIC_URL`), the browser's `Cookie` as it came,
  and the page's path and query as `referer`.
- `Net::HTTP` never follows a redirect, so a droplet's 3xx is kept:
  `shop_render` answers it with `halt`, and sends the fragments' `Set-Cookie`
  with the page.
- Only a `text/html` answer (a 2xx, or a 500 carrying the droplet's error
  page) is pasted; `<%= %>` prints it unescaped.
- `views/shop/layout.erb` loads `/index.js` once. `SHOP_PROXIED`, routed for
  every verb, passes `/index.js`, `/droplets/*`, `/assets/*` and `/api/*` on
  to the shop.

### Pieces and ports

`docker-compose.yml` starts three services:

| Service | Port | What it is |
| --- | --- | --- |
| `web` | 8002, public | Sinatra: the shop's pages, the proxy, and the basic page at `/` |
| `shop` | 8300, internal only | the shop's droplets server (`examples/shop`) |
| `droplets` | 8000, public | the Svelte example's droplets server, for `/` only |

| On `web` | Value | Used for |
| --- | --- | --- |
| `SHOP_INTERNAL_URL` | `http://shop:8300` | internal: fragment fetches and the proxy |
| `SHOP_PUBLIC_URL` | `http://localhost:8002` | public: this host's own origin, sent as `x-droplet-location` |
| `DROPLETS_INTERNAL_URL`, `DROPLETS_PUBLIC_URL` | `http://droplets:8000`, `http://localhost:8000` | the same pair, for the basic page |

### How a page gets a droplet

A server fetch with `Net::HTTP`, one thread per fragment, rendered into ERB.
The fetch is `shop_fragment` and the view is `views/shop/gallery.erb`, both
shown in the pattern above; the fragments' `Link` preloads go into `<head>`.
`shop_render` runs the fetches:

```ruby
results = requests.map { |id, params| Thread.new { shop_fragment(id, params) } }.map(&:value)
```

`referer` is the page's path and query as the browser sent it: the
droplet's [`host`](/integrate/http-contract/#host-where-the-droplet-renders).
`views/shop/layout.erb` loads `<script type="module" src="/index.js">` once,
through the proxy, and each droplet hydrates itself. `shop_render` fetches
the toasts and the header's cart badge with every page's fragments; the
`toast-center` fragment comes first in the body, and `/index.js` installs
`window.shopMessageQueue` before any droplet starts (the shop's
`src/hooks.client.ts`):

```erb
<body class="shop">
<%= @shop[:toasts] %>
<header class="shop-header">…<div class="shop-cart"><%= @shop[:cart] %></div>…</header>
```

### What it proxies

`SHOP_PROXIED = %r{/(?:index\.js|(?:droplets|assets|api)/.*)}`, routed for
every verb to `shop_proxy`: `/index.js`, `/droplets/*` (fragments, `_data`,
form actions), `/assets/*` and `/api/*` go to the shop with `x-droplet-location` written
out, and the answer comes back with `Set-Cookie` and redirects untouched.
The shop's cookies are first-party, and nothing is cross-origin; the shop
sets them only from form actions and `/api`, which come through here.

### The shop's environment

- `DROPLETS_TRUSTED_ORIGINS: http://localhost:8002`: the only origin whose
  [`x-droplet-location`](/integrate/http-contract/#x-droplet-location-the-public-location) and
  [form posts](/integrate/http-contract/#form-posts-the-origin-check) the shop accepts.
- `DROPLETS_SECRET`: signs a form's result on the redirect back to the page
  when JavaScript is off ([Post/Redirect/Get](/integrate/http-contract/#postredirectget)).
- `ADMIN_USER`, `ADMIN_PASSWORD`, `SHOP_SECRET`: the demo login
  (admin / droplets) and the key its cookie is signed with. Demo values only.

### Gotchas

- **Sinatra reads a form body before the route runs**, and the server's input
  cannot be rewound. A small middleware (`ShopBufferedInput`) buffers it so
  the proxy can pass the same body on, and `method_override` is off, since
  `Rack::MethodOverride` would read it even earlier.
- **Sinatra's ERB does not escape `<%= %>` by default**, which is how the
  fragments are pasted; the views escape everything else with `h()`. See [For hosts](/guides/security/#for-hosts).

### Run it

```bash
cd examples/hosts/sinatra
docker compose up --build
open http://localhost:8002/gallery   # log in as admin / droplets
```

## The Svelte example

The same app serves the Svelte example at `/`: its three droplets, one per mode, from `examples/frameworks/svelte` (the `droplets` service).

```ruby
DROPLETS_INTERNAL_URL = ENV.fetch("DROPLETS_INTERNAL_URL", "http://localhost:8000")
DROPLETS_PUBLIC_URL = ENV.fetch("DROPLETS_PUBLIC_URL", "http://localhost:8000")

def fetch_droplet(droplet, props = {})
  uri = URI("#{DROPLETS_INTERNAL_URL}/droplets/#{droplet}")
  uri.query = URI.encode_www_form(props) unless props.empty?

  response = Net::HTTP.start(uri.host, uri.port, read_timeout: 5) do |http|
    http.get(uri.request_uri, { "x-droplet-location" => DROPLETS_PUBLIC_URL })
  end
  return response.body if response.is_a?(Net::HTTPSuccess)

  %(<p class="error">droplet "#{droplet}" unavailable: HTTP #{response.code}</p>)
end

get "/" do
  @droplets_public_url = DROPLETS_PUBLIC_URL
  who = params.fetch("who", "Sinatra")
  @fragments = %w[svelte vue react solid handlebars].map { |framework| fetch_droplet("#{framework}-ssr-hydrate", who: who) }
  erb :index
end
```

```erb
<script type="module" src="<%= @droplets_public_url %>/index.js"></script>
...
<% @fragments.each do |fragment| %>
  <%= fragment %>
<% end %>
```

Rails works the same way: fetch in the controller, `raw` or `html_safe` in the
view.

The example lives in `examples/hosts/sinatra`. The page and the droplets
server are different origins, so the droplets server runs with `cors: true`.
