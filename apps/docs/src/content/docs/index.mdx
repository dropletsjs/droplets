Droplets serves each of your components at its own URL, as a fragment of
server-rendered HTML. Any server that can make an HTTP request (nginx, PHP,
WordPress, Express, Next.js, FastAPI) fetches the fragment, pastes it into its
page and loads one script; the component then comes alive there, with its
own data, styles and JavaScript.

It is for teams that need the same interactive widgets in several apps or
stacks, that add components to an existing site piece by piece, or that ship
UI on their own schedule. For one application in one framework, that
framework's own meta-framework does the job better.

```html
<!-- Any page, any server: paste the fragment, load one script. -->
<script type="module" src="https://drops.example.com/index.js"></script>

<acme-widgets data-droplet="hello">
  <!-- GET https://drops.example.com/droplets/hello?who=Ana -->
  <h1>Hello Ana!</h1>
</acme-widgets>
```

## Where it comes from

Droplets grew out of SvelteKit: `+` files, loads, form actions,
hooks and prerendering, reshaped for components that live inside someone
else's page. It is an independent project, not affiliated with Svelte or
SvelteKit. [What is a droplet?](/start/what-is-a-droplet/) explains the rest.
