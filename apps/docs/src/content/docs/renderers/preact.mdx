## The files

| File | What it is |
| --- | --- |
| `+droplet.tsx`, `+droplet.jsx` | The component, the file's default export. Its flags are named exports. |
| `+error.tsx`, `+error.jsx` | The error page, optional. |
| `+droplet.ts`, `+droplet.server.ts` | The loads, as for every framework: [Writing droplets](/guides/writing-droplets/#the-load-chain). |

### Which `.tsx` files are Preact's

Preact has no extension of its own: it shares `.tsx` and `.jsx` with React,
Solid and Hono JSX. With Preact the only one of them in `renderers`, every
`.tsx` droplet is Preact's. With two or more, each droplet file says which
it is:

1. **An import** of `preact`, `preact-render-to-string` or
   `@dropletsjs/renderer-preact`, a subpath included (`preact/hooks`): the
   file is Preact's. The demo's counter imports `preact/hooks`.
2. **Otherwise a comment**, `/** @jsxImportSource preact */`, decides. `djs add`
   writes it at the top of every Preact component, and it is also what types
   the file's JSX for Preact when `tsconfig.json` names another
   `jsxImportSource`, as apps/demo's (`react`) does.

A name such as `+droplet.preact.tsx` would not help: it still ends in
`.tsx`, which the other three claim as well.

```tsx
// src/droplets/hello/+droplet.tsx
import { useState } from "preact/hooks";
import type { DropletProps } from "./$types";

export const hydrate = true;

export default function Hello({ data, children }: DropletProps) {
  const [clicks, setClicks] = useState(0);
  // Always the value: the renderer awaits a promise of it before rendering.
  return (
    <>
      <h1>{data.greeting}</h1>
      <button onClick={() => setClicks((n) => n + 1)}>{clicks}</button>
      {children}
    </>
  );
}
```

```tsx
// src/droplets/hello/+error.tsx
/** @jsxImportSource preact */
import type { DropletErrorProps } from "./$types";
import "./error.css";

export default function HelloError({ error, children }: DropletErrorProps) {
  return (
    <>
      <p class="oops">{error.message}</p>
      {children}
    </>
  );
}
```

## What it supports

| | |
| --- | --- |
| Server rendering | yes: `ssr = true`, the default; `ssr = false` mounts it in the browser only (`render`) |
| `hydrate` | `true` (the default), `"visible"`, `"interactive"`, `false` |
| Prerendering | yes: `prerender = true` with `entries` |
| Forms | `useEnhanceDropletForm(formRef, options?)` of `@dropletsjs/renderer-preact/form` |

What it does not do fails the build and says why:

- a `.tsx` droplet that names no framework, or two, when several share the
  extension:

  ```
  droplets: counter/+droplet.tsx: react, solid, preact and hono-jsx all handle this file and it imports none of them; import from react, solid-js, preact or hono/jsx, or add a /** @jsxImportSource <package> */ comment
  ```

- importing React, which nothing aliases to `preact/compat`, or any other
  framework, even through a neutral file:

  ```
  droplets: a preact droplet imports react code: src/droplets/counter/+droplet.tsx -> src/droplets/counter/lib.ts -> react/index.js. A droplet uses its own framework's modules and neutral code only.
  ```

A flag that is not a literal (`export const hydrate = isMobile`) is ignored,
with a warning.

## Specifics

- **Data is always the value.** Preact has no `use(promise)`: when the
  element mounts a droplet from scratch (client-only, refreshed in dev), the
  renderer awaits its `data` first, then renders. A rejection shows
  `+error.tsx`, and a render error later on reaches the renderer's error
  boundary, which shows it too.
- **Hydration is synchronous.** `hydrate` and `render` both return with the
  droplet live.
- **JSX:** the renderer compiles its modules with Preact's automatic runtime
  (`preact/jsx-runtime`) itself, without `@preact/preset-vite`. Nothing
  aliases `react` to `preact/compat`, so React droplets in the same project
  keep React. Attributes are HTML's: `class`, `for`.
- **Children:** `children` renders the host's content.
- **Styles:** imported CSS goes to the droplet's stylesheet.
- **Forms:** keep the action's URL from the first render,
  `const [add] = useState(() => actionUrl("add"))` with `actionUrl` of
  `$droplets/form`, then `<form method="post" action={add}>`.
- **Hot updates:** Prefresh, under `vite dev` with `dev.strategy: "hmr"`
  (the default), on any page that loads `index.js` from the dev server. An
  edit to a component keeps its hook state. The renderer compiles Prefresh
  into Preact's modules only, in its own transform, so nothing of it reaches
  a React or Solid module next to it. An edit to the load brings new `data`
  to the live component, its state kept. See [Hot updates](/guides/development/#hot-updates).
- **Options:** `preact({ plugin: false })` leaves compiling to you: both
  builds then need Preact's automatic runtime, `jsxImportSource: "preact"`.

## The example

[`examples/frameworks/preact`](https://github.com/dropletsjs/droplets/tree/main/examples/frameworks/preact)
has one droplet per mode (`client`, `ssr-hydrate` with an error page,
`ssr-nohydrate`), with loads, a props schema, `/api` endpoints, env variables
and a `handle` hook. From a clone of the repository:

```bash
pnpm install && pnpm build
pnpm --filter @dropletsjs/example-preact dev   # http://localhost:5173: the devtools page
```

`pnpm --filter @dropletsjs/example-preact build` then `start` serves it on
http://localhost:8000; `/droplets/ssr-hydrate?who=Ana` is the fragment a
host pastes into its page.
