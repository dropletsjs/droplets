Handlebars templates, precompiled at build and rendered on the server with
`handlebars/runtime`. A template has no code of its own in the browser:
there is nothing to hydrate it with. The droplet below is the same counter as
on the other pages, rendered by the same demo server, and it stops there: it
shows the start from the load, but there is no button, because nothing in
the page could make one count.

## Add it to a project

<AddRenderer framework="handlebars" />

## The files

| File | What it is |
| --- | --- |
| `+droplet.hbs` | The template. Its flags go in the comment it opens with, or in `+droplet.ts`. |
| `+error.hbs` | The error page, optional. |
| `src/partials/**/*.hbs` | Partials, registered by their path without the extension: `{{> footer}}`, `{{> cards/item}}`. |
| `src/handlebars.ts` | Helpers: every exported function is a helper of the same name, on the server and in the browser. |
| `+droplet.ts`, `+droplet.server.ts` | The loads, as for every framework: [Writing droplets](/guides/writing-droplets/#the-load-chain). |

`.hbs` is Handlebars' alone: any `+droplet.hbs` is a Handlebars droplet.

A template sees `{{data.…}}` (what the loads returned), `{{form.…}}` after a
form action, `{{error.…}}` in the error page and `{{{children}}}` for the
host's content (triple braces: it is HTML). `@droplet`, `@kind` and
`@renderId` are data variables of the render.

```hbs
{{!-- src/droplets/hello/+droplet.hbs --}}
{{!--
export ssr = true
export hydrate = false
--}}
<h1>{{data.greeting}}</h1>
<p>{{upper data.who}}</p>
{{> footer}}
{{{children}}}

<style>
  h1 { font-family: system-ui, sans-serif; }
</style>
<style src="./theme.css"></style>
```

```hbs
{{!-- src/droplets/hello/+error.hbs --}}
<p class="oops">{{error.message}}</p>
{{{children}}}

<style>
  .oops { color: crimson; }
</style>
```

```ts
// src/handlebars.ts: every exported function is a helper
export const upper = (value: unknown) => String(value).toUpperCase();
```

## What it supports

| | |
| --- | --- |
| Server rendering | yes: `ssr = true`, the default; `ssr = false` renders the template in the browser instead |
| `hydrate` | `true` (the default), `"visible"`, `"interactive"`, `false`; none adds behaviour, see below |
| Prerendering | yes: `prerender = true` with `entries` |
| Forms | `<form method="post" action="{{action "add"}}">`, posted natively; `data-droplets-enhance` posts it by `fetch` |

What it does not do fails the build and says why. The flags comment is
checked strictly:

```
droplets: counter/+droplet.hbs: flags go in the comment the template starts with, before anything else
```

```
droplets: counter/+droplet.hbs: flag "hydrate" must be true, false, "visible" or "interactive", found "maybe"
```

```
droplets: counter: "hydrate" is declared in both +droplet.hbs and +droplet.ts; keep one
```

and so is a `<style>` block, which is static CSS:

```
droplets: src/droplets/counter/+droplet.hbs:1: a <style> block cannot contain {{…}}: CSS is static
```

## Specifics

- **No behaviour in the browser.** A template is HTML with holes; Handlebars
  has no events or state, so the renderer has nothing to attach. `hydrate`
  keeps the server's HTML and wires the host's children into it; `mount`
  renders the template in the browser (an `ssr = false` droplet, an error
  page shown there, a remount in dev), after awaiting a load's promise. For
  a droplet without children or a browser `load`, `hydrate = false` is the
  lean choice, as in the demo: no JavaScript at all for it. With
  `hydrate = true` the same counter loads 6.9 kB (gzip) for the runtime and
  the template, and still shows no button.
- **A button that does something** needs one of two things:
  - a form: `{{action "add"}}` writes where it posts for an action in
    `+droplet.server.ts`, and `data-droplets-enhance` on the `<form>` makes
    `/index.js` post it by `fetch` and render the result in place, even with
    `hydrate = false` (the server renders the fragment again). See
    [Actions](/guides/writing-droplets/#actions);
  - or browser code next to it, in another droplet: a
    [plain script](/renderers/script/) builds its own UI from its data.
- **Templates** are precompiled at build; only `handlebars/runtime` ships,
  on the server and, for a droplet that hydrates, in the browser.
- **Partials and helpers** go into the renderer's own Handlebars
  environment, never the global one. `action` and `children` are the
  renderer's helpers; a project helper by those names is ignored.
- **Styles** are `<style>` blocks in `+droplet.hbs` and `+error.hbs`, inline
  or with `src` (a file, relative to the template). They are taken out of the
  template at build, in order, and become the droplet's stylesheet like a
  component's CSS elsewhere: through Vite (PostCSS, Tailwind, `lang="scss"`),
  scoped to the element, nothing left in the HTML. A block is static: at the
  top of the template, outside `{{#…}}` blocks, with no `{{…}}` inside.
  Partials have none, since every droplet registers them.
- **Flags** are `export <flag> = <value>` lines in the opening comment, one
  per line or all on one line (`{{!-- export hydrate = false; export prerender = true --}}`).
  `+error.hbs` follows the droplet's flags.
- **Options:** `handlebars({ partials, helpers, compile })` moves the
  partials folder (`false` for none) or the helpers module (`false` for
  none), and passes options to `Handlebars.precompile` (`strict`,
  `noEscape`, …).
- **Hot updates:** an edited template remounts the droplet under `vite dev`
  ([`dev.strategy`](/guides/development/#hot-updates)).

## The example

[`examples/frameworks/handlebars`](https://github.com/dropletsjs/droplets/tree/main/examples/frameworks/handlebars)
has one droplet per mode (`client`, `ssr-hydrate` with an error page,
`ssr-nohydrate`), with loads, a props schema, `/api` endpoints, env variables
and a `handle` hook. From a clone of the repository:

```bash
pnpm install && pnpm build
pnpm --filter @dropletsjs/example-handlebars dev   # http://localhost:5173: the devtools page
```

`pnpm --filter @dropletsjs/example-handlebars build` then `start` serves it
on http://localhost:8000; `/droplets/ssr-hydrate?who=Ana` is the fragment a
host pastes into its page.
