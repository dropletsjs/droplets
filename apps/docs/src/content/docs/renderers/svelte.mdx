Svelte 5 components, in runes mode, rendered on the server and hydrated in
place. The droplet below is a Svelte component served by the demo server:
its load sets the start, Svelte renders it to HTML, and the button works once
the bundle hydrates it.

## Add it to a project

<AddRenderer framework="svelte" />

## The files

| File | What it is |
| --- | --- |
| `+droplet.svelte` | The component. Its flags go in `<script module>`. |
| `+error.svelte` | The error page, optional. Its styles travel with its markup. |
| `*.svelte.ts`, `*.svelte.js` | Svelte modules with runes, anywhere in `src/`: Svelte's own, so only Svelte droplets may import them. |
| `+droplet.ts`, `+droplet.server.ts` | The loads, as for every framework: [Writing droplets](/guides/writing-droplets/#the-load-chain). |

`.svelte` is Svelte's alone, so nothing decides between renderers here: any
`+droplet.svelte` is a Svelte droplet.

The props are `data` (what the loads returned), `form` after a form action,
and `children`, a snippet for the host's content:

```svelte
<!-- src/droplets/hello/+droplet.svelte -->
<script module lang="ts">
  export const hydrate = true;
</script>

<script lang="ts">
  import type { DropletProps } from "./$types";

  let { data, children }: DropletProps = $props();
  let clicks = $state(0);
</script>

{#await data then { greeting }}
  <h1>{greeting}</h1>
{/await}
<button onclick={() => (clicks += 1)}>{clicks}</button>
{@render children?.()}
```

```svelte
<!-- src/droplets/hello/+error.svelte -->
<script lang="ts">
  import type { DropletErrorProps } from "./$types";
  let { error, children }: DropletErrorProps = $props();
</script>

<p class="oops">{error.message}</p>
{@render children?.()}

<style>
  .oops { color: crimson; }
</style>
```

## What it supports

| | |
| --- | --- |
| Server rendering | yes: `ssr = true`, the default; `ssr = false` mounts it in the browser only |
| `hydrate` | `true` (the default), `"visible"`, `"interactive"`, `false` |
| Prerendering | yes: `prerender = true` with `entries` |
| Forms | `use:enhanceDropletForm` of `@dropletsjs/renderer-svelte/form` |

What it does not do fails the build and says why:

- importing another framework, even through a neutral file:

  ```
  droplets: a svelte droplet imports vue code: src/droplets/counter/+droplet.svelte -> vue/dist/vue.runtime.esm-bundler.js. A droplet uses its own framework's modules and neutral code only.
  ```

- a second component in the folder:

  ```
  droplets: counter/ has 2 droplet components (+droplet.svelte, +droplet.vue); keep one
  ```

Two mistakes only warn: a flag that is not a literal
(`export const hydrate = isMobile`) is ignored, and an `+error.vue` next to a
Svelte droplet is ignored, with a warning in dev.

## Specifics

- **Compiler options.** Runes mode and `vitePreprocess()` are on, and
  `svelte.config.js` is read as usual. `svelte({ vitePlugin })` passes options
  to `@sveltejs/vite-plugin-svelte`: its `compilerOptions` and `preprocess`
  are merged with the renderer's, the rest replaces them. With
  `svelte({ plugin: false })` you register the plugin yourself; it then needs
  runes mode, `vitePreprocess()`, and `css: "injected"` for `+error.svelte`
  through `dynamicCompileOptions`.
- **Data is a value**, unless you turn on Svelte's `experimental.async`. The
  renderer never turns it on; it reads whether you did. Without it, a
  droplet mounted in the browser from scratch (client-only, refreshed in dev)
  waits for its data before mounting, so `data.greeting` works everywhere.
  With it, such a droplet gets `data` as a promise: read it with
  `{(await data).greeting}`, and a rejection reaches the renderer's boundary
  (or your own `<svelte:boundary>`). `{#await data}` works in both modes, as
  in the demo, but without `{:catch}` it does not report a rejection.
- **Children.** `{@render children?.()}` renders the host's content. It may
  sit under an `{#if}`: the content is moved out and back, never destroyed.
- **The error page** compiles with injected CSS, so its `<style>` travels
  with the markup wherever it renders, even where the droplet's stylesheet
  never loaded.
- **Hot updates.** Under `vite dev`, an edit to a component goes through
  Svelte's own HMR, on any page that loads `index.js` from the dev server;
  see [Hot updates](/guides/development/#hot-updates).

## The example

[`examples/frameworks/svelte`](https://github.com/dropletsjs/droplets/tree/main/examples/frameworks/svelte)
has one droplet per mode (`client`, `ssr-hydrate` with an error page,
`ssr-nohydrate`) and a script droplet, `page-views`, with loads, a props
schema, `/api` endpoints, env variables and a `handle` hook. From a clone of
the repository:

```bash
pnpm install && pnpm build
pnpm --filter @dropletsjs/example-svelte dev   # http://localhost:5173: the devtools page
```

`pnpm --filter @dropletsjs/example-svelte build` then `start` serves it on
http://localhost:8000; `/droplets/ssr-hydrate?who=Ana` is the fragment a
host pastes into its page.
