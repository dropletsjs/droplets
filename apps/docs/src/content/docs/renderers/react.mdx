## The files

| File | What it is |
| --- | --- |
| `+droplet.tsx`, `+droplet.jsx` | The component, the file's default export. Its flags are named exports. |
| `+error.tsx`, `+error.jsx` | The error page, optional. |
| `+droplet.ts`, `+droplet.server.ts` | The loads, as for every framework: [Writing droplets](/guides/writing-droplets/#the-load-chain). |

### Which `.tsx` files are React's

React shares `.tsx` and `.jsx` with Preact, Solid and Hono JSX. With React
the only one of them in `renderers`, every `.tsx` droplet is React's. With
two or more, each droplet file says which it is:

1. **An import** of `react`, `react-dom` or `@dropletsjs/renderer-react`, a
   subpath included (`react/jsx-runtime`): the file is React's.
2. **Otherwise a comment**, `/** @jsxImportSource react */`, decides. `djs add`
   writes it at the top of every React component, and it is also what types
   the file's JSX for React when `tsconfig.json` names another
   `jsxImportSource`.

The first `.tsx` framework `djs add` installs sets `"jsx": "react-jsx"` in
`tsconfig.json` with its own `jsxImportSource`: `"react"` for React. That
setting only types the files; the renderer compiles React's modules with
React's JSX runtime whatever it says.

```tsx
// src/droplets/hello/+droplet.tsx
import { use, useState } from "react";
import type { DropletProps } from "./$types";

export const hydrate = true;

export default function Hello({ data, children }: DropletProps) {
  const [clicks, setClicks] = useState(0);
  // A value when hydrating, a promise when mounted from scratch.
  const { greeting } = data instanceof Promise ? use(data) : data;
  return (
    <>
      <h1>{greeting}</h1>
      <button onClick={() => setClicks((n) => n + 1)}>{clicks}</button>
      {children}
    </>
  );
}
```

```tsx
// src/droplets/hello/+error.tsx
import type { DropletErrorProps } from "./$types";
import "./error.css";

export default function HelloError({ error, children }: DropletErrorProps) {
  return (
    <>
      <p className="oops">{error.message}</p>
      {children}
    </>
  );
}
```

## What it supports

| | |
| --- | --- |
| Server rendering | yes: `ssr = true`, the default; `ssr = false` mounts it in the browser only (`createRoot`) |
| `hydrate` | `true` (the default), `"visible"`, `"interactive"`, `false` |
| Prerendering | yes: `prerender = true` with `entries` |
| Forms | `useEnhanceDropletForm(formRef, options?)` of `@dropletsjs/renderer-react/form` |

What it does not do fails the build and says why:

- a `.tsx` droplet that names no framework, or two, when several share the
  extension:

  ```
  droplets: counter/+droplet.tsx: react, solid, preact and hono-jsx all handle this file and it imports none of them; import from react, solid-js, preact or hono/jsx, or add a /** @jsxImportSource <package> */ comment
  ```

- importing another framework, even through a neutral file:

  ```
  droplets: a react droplet imports solid code: src/droplets/counter/+droplet.tsx -> src/droplets/counter/lib.ts -> solid-js/dist/solid.js. A droplet uses its own framework's modules and neutral code only.
  ```

A flag that is not a literal (`export const hydrate = isMobile`) is ignored,
with a warning.

## Specifics

- **Data as a promise:** `use(data)` suspends while it is one (a droplet
  mounted from scratch: client-only, refreshed in dev); a rejection reaches
  the renderer's error boundary, which shows `+error.tsx`.
- **Children:** `children` renders the host's content.
- **Styles:** imported CSS goes to the droplet's stylesheet.
- **Forms:** keep the action's URL from the first render,
  `const [add] = useState(() => actionUrl("add"))` with `actionUrl` of
  `$droplets/form`, then `<form method="post" action={add}>`.
- **Fast Refresh** works on any host page under `vite dev`, with
  `dev.strategy: "hmr"` (the default). The renderer installs React's
  preamble itself and compiles it into React's modules only, never another
  framework's. As in any React app, an edit keeps the component's state
  when every export of the file is a component or unchanged. The flags
  (`ssr`, `hydrate`, `prerender`) are exports Fast Refresh ignores. A new
  value for one is a new render contract, which shows a notice and leaves
  the droplet as it is. Another non-component export whose value changes
  makes Fast Refresh give up, and the droplet remounts in place: the page
  never reloads. An edit to the load (`+droplet.server.ts`, `+droplet.ts`)
  brings new `data` to the live component, which keeps its state. See
  [Hot updates](/guides/development/#hot-updates).
- **Options:** `react({ vitePlugin })` passes options to
  `@vitejs/plugin-react`. With `react({ plugin: false })` you register the
  plugin yourself; the renderer still needs it there, since the Fast Refresh
  preamble comes from it.

## The example

[`examples/frameworks/react`](https://github.com/dropletsjs/droplets/tree/main/examples/frameworks/react)
has one droplet per mode (`client`, `ssr-hydrate` with an error page,
`ssr-nohydrate`), with loads, a props schema, `/api` endpoints, env variables
and a `handle` hook. From a clone of the repository:

```bash
pnpm install && pnpm build
pnpm --filter @dropletsjs/example-react dev   # http://localhost:5173: the devtools page
```

`pnpm --filter @dropletsjs/example-react build` then `start` serves it on
http://localhost:8000; `/droplets/ssr-hydrate?who=Ana` is the fragment a
host pastes into its page.
