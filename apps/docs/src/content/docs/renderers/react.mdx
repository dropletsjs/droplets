## The files

| File | What it is |
| --- | --- |
| `+droplet.tsx`, `+droplet.jsx` | The component, the file's default export. Its flags are named exports of this file. |
| `+error.tsx`, `+error.jsx` | The error page, optional. It follows the droplet's flags. |
| `+droplet.ts`, `+droplet.server.ts` | The loads, as for every framework: [Writing droplets](/guides/writing-droplets/#the-load-chain). |

The flags are literal `export const` declarations of the component file. A
flag exported from `+droplet.ts` or `+droplet.server.ts` is ignored.

**Which `.tsx` files are React's.** When React is the only `.tsx`
framework in `renderers`, all of them. Next to Preact, Solid or Hono JSX, a droplet file is
React's when it imports `react`, `react-dom` or `@dropletsjs/renderer-react`, a subpath included (`react/jsx-runtime`), or carries a `/** @jsxImportSource react */`
comment (`djs add` writes one at the top of every React component), and
names no other `.tsx` framework. See
[Which renderer a `.tsx` file belongs to](/renderers/#which-renderer-a-tsx-file-belongs-to).

```tsx
// src/droplets/hello/+droplet.tsx
import { use, useState } from "react";
import type { DropletProps } from "./$types";

export const hydrate = true;

export default function Hello({ data, children }: DropletProps) {
  const [clicks, setClicks] = useState(0);
  // A value when hydrating, a promise when mounted from scratch.
  const { greeting } = data instanceof Promise ? use(data) : data;
  return (
    <>
      <h1>{greeting}</h1>
      <button onClick={() => setClicks((n) => n + 1)}>{clicks}</button>
      {children}
    </>
  );
}
```

```tsx
// src/droplets/hello/+error.tsx
import type { DropletErrorProps } from "./$types";
import "./error.css";

export default function HelloError({ error, children }: DropletErrorProps) {
  return (
    <>
      <p className="oops">{error.message}</p>
      {children}
    </>
  );
}
```

`error` is what `handleError` in `+droplet.server.ts` (or `+droplet.ts`)
returned; see [Errors](/guides/errors/).

## What it supports

| | |
| --- | --- |
| Server rendering | yes: `ssr = true`, the default; `ssr = false` mounts it in the browser only (`createRoot`) |
| `hydrate` | `true` (the default), `"visible"`, `"interactive"`, `false` |
| Prerendering | yes: `prerender = true`, once per event `entries` returns: [Prerendering](/guides/prerendering/) |
| Forms | `useEnhanceDropletForm(formRef, options?)` of `@dropletsjs/renderer-react/form` |

Two mistakes fail `vite build`, and `vite dev` as well, with a message that
names the fix:

- a `.tsx` droplet that names no framework, or two, when several share the
  extension. With `react()` and `preact()` in `renderers`:

  ```
  droplets: counter/+droplet.tsx: react and preact both handle this file and it imports neither; import from react or preact, or add a /** @jsxImportSource <package> */ comment
  ```

  The message lists every renderer that shares the extension, in the order
  of `renderers`.

- a React droplet that reaches another configured framework, even through a
  neutral file:

  ```
  droplets: a react droplet imports preact code: src/droplets/counter/+droplet.tsx -> src/lib/preact-label.ts -> preact/dist/preact.mjs. A droplet uses its own framework's modules and neutral code only.
  ```

Other mistakes are ignored, with a warning:

- a flag that is not a literal, such as `export const hydrate = isMobile`,
  warns under `vite dev` and `vite build`, and the flag keeps its default:

  ```
  [droplets:framework] `export const hydrate` must be true, false, "visible" or "interactive"; ignoring it { droplet: 'counter', found: 'isMobile' }
  ```

- an `+error.tsx` that names another framework is not used; under
  `vite dev` and `vite build` warn once
  `counter/+error.tsx is not a react component like the droplet; ignored, the error page is written in the droplet's framework`.

## Specifics

- **Data as a promise:** `use(data)` suspends while it is one (a droplet
  mounted from scratch: client-only, remounted in dev). With an error page,
  the droplet renders under `<Suspense>` inside the renderer's error
  boundary, and a rejection, or anything else that throws while rendering,
  shows `+error.tsx` with what `handleError` returned.
- **Children:** `children` renders the host's content, in `+droplet.tsx`
  and in `+error.tsx`.
- **Styles:** imported CSS goes to the droplet's stylesheet, the error
  page's included: React components carry no inline styles, and the element
  links that stylesheet whenever the droplet is on the page.
- **Forms:** keep the action's URL from the first render,
  `const [add] = useState(() => actionUrl("add"))` with `actionUrl` of
  `$droplets/form`, then `<form method="post" action={add}>`.
  `useEnhanceDropletForm(formRef, { action: "add" })` sends it with `fetch`
  and shows the result in place; without `onResult`, it calls
  `result.update()`. See [Actions](/guides/actions/).
- **Errors in the browser:** React's recoverable, uncaught and caught errors
  go to `console.error` as `[droplets] <droplet> (<kind>, react)`; what the
  renderer's own boundary catches is reported by the framework instead.
- **Fast Refresh** works on any host page under `vite dev`, with
  `dev.strategy: "hmr"` (the default). The renderer installs React's
  preamble itself and compiles Fast Refresh into React's modules only, never
  another framework's. As in any React app, an edit keeps the component's
  state when every export of the file is a component or unchanged. The flags
  (`ssr`, `hydrate`, `prerender`) are exports Fast Refresh ignores. A new
  value for one is a new render contract, which shows a notice and leaves
  the droplet as it is. Another non-component export whose value changes
  makes Fast Refresh give up, and the droplet remounts in place: the page
  never reloads. An edit to the load (`+droplet.server.ts`, `+droplet.ts`)
  brings new `data` to the live component, which keeps its state. See
  [Hot updates](/guides/development/#hot-updates).
- **Options:** `react({ vitePlugin })` passes options to
  `@vitejs/plugin-react`. With `react({ plugin: false })` you register the
  plugin yourself; the renderer still needs it there, since the Fast Refresh
  preamble comes from it.

## The example

[`examples/frameworks/react`](https://github.com/dropletsjs/droplets/tree/main/examples/frameworks/react)
has one droplet per mode, `client` (`ssr = false`), `ssr-hydrate` (with
`+error.tsx`) and `ssr-nohydrate` (`hydrate = false`), with loads, a props
schema, `/api` endpoints, env variables and a `handle` hook. Its droplets
render in `<djs-react>`. From a clone of the repository:

```bash
pnpm install && pnpm build
pnpm --filter @dropletsjs/example-react dev   # http://localhost:5173: the devtools page
```

`pnpm --filter @dropletsjs/example-react build` then `start` serves it on
http://localhost:8000; `/droplets/ssr-hydrate?who=Ana` is the fragment a
host pastes into its page.
